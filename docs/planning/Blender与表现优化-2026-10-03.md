# Blender与表现优化 · 2026-10-03

状态：设计准备，未执行新增美术。现有三兵种Blender源文件和FBX已完成第一版；它们并非最终LOL手绘质感。方向仍是“炉石式有重量的UI交互，LOL式战场造型”。

## 制作分工

Blender负责网格、雕刻、UV、烘焙贴图、骨骼/权重、动画和可重复渲染的图标/序列帧。Unity负责交互状态、镜头、实际灯光/着色器、粒子/拖尾、音频和联机事件演出。不能把Blender棚拍质量直接视为游戏实时质量。[Blender烘焙说明](https://docs.blender.org/manual/de/4.5/render/cycles/baking.html)

当前为Built-in渲染管线和自有棋盘着色器。优先内置Particle System、Trail/LineRenderer和轻量着色器。VFX Graph面向URP/HDRP；若确需它，先做独立URP兼容验证，检查棋盘材质、UI3D相机、透明排序、水晶和字体，再决定迁移，不为一个火焰顺手重构整个管线。[Unity兼容表](https://docs.unity3d.com/6000.0/Documentation/Manual/ChoosingYourParticleSystem.html)

## 动画接口与复杂时序

建议定义展示事件适配层：来源事件ID、动作ID/父动作ID、角色/目标、起终点、结果、可见范围。实际字段先对现有事件审计再定，不改Command/View就能解决的演出先在本地投影适配。

移动按规则已接受路径播放；先攻修正只重排未执行主卡。防御/被弃牌镜头对准响应者；反击遵循D-044，原行动完整结束后新增一级行动节点。播放队列必须可跳过、加速和重连重置，不能阻塞待决策交互或把重复事件播两遍。真正用于判定的棋子位置来自规则，不来自Root Motion或物理碰撞。

## 样板协作流程

1. 用户提供一张造型参考、一段5—15秒动态参考，并指明要的是材质、动作节奏还是镜头，列两个不喜欢的点。不同参考冲突时先指出。
2. 制作一张比例/色板草图和一个短灰模动作，先定剪影与时间，不一次铺到全体。
3. 做单个高质量样板：建议近战兵一次攻击＋一个按钮的正常/hover/按下/弃置/回收五状态。
4. 给同一机位连续实录，按秒标记反馈：“0.3秒起手太慢”“命中光太亮挡住格子”。分别验收动作、材质、声音、游戏可读性。
5. 模板通过后再批量；保留源资产、导出参数、材质槽、动作命名、贴图源、LOD和版本记录。

起步预算建议（待真实测量，不是既定指标）：小兵优先减少当前8k—12.5k三角面在远视角的成本；同阵营共享材质、控制透明重叠、同时特效数量和贴图尺寸，给低/中/高效果档。单个模型好看但满棋盘掉帧不算通过。还需提供减少镜头运动/闪光的选项。

建议第一张任务：不改规则、网络和卡牌UI布局，只精修近战兵，做待机/行走/攻击三个动作，在真实棋盘测试路径起停、快速连续更新和重连恢复；提供Blender源、Unity样板、连续视频与性能对比，再推广其他模型。
