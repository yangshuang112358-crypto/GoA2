# NET-01：四身份联网的实施与验收设计

状态：设计，未实施。依据[ADR-005](../architecture/decisions/ADR-005-四身份联网切片.md)，四席0—3，UI1—4，单一服务权威，首批仅同机回环。现有21张牌、场景和GameSession投影是输入，不以联网工作代替剩余牌实现。

## 可独立验收的步骤

| 顺序 | 工作 | 可审查产物 | 通过后才能继续 |
|---|---|---|---|
| 1 | 定义封套和每种Intent字段 | WireVersion、严格解析器、帧大小测量、最小消息样例 | 缺失/未知/重复字段、布尔伪整数、未知枚举、超长消息在规则调用前失败 |
| 2 | 房间与连接绑定 | 四个不同凭证、席位绑定、连接代次、单房间队列 | 伪造身份/跨房间/第五席/失效连接不能取得本人以外视图 |
| 3 | 实际服务和四客户端 | 可启动进程、端口/退出清理、独立日志 | 经真实传输完成准备和四人确认；日志没有凭证、全手牌或全存档 |
| 4 | 结果、重试和续连 | CommandId保留、revision更新、重复/冲突处理 | 注入丢回复、延迟、重连，奖励与弃牌仍只执行一次 |
| 5 | Unity客户端适配 | 本人固定手牌、等待/断线状态、合法查询和确认 | 四个可见实例操作一整轮；1—4不改变网络身份 |
| 6 | 待选择恢复与证据 | 防御、可选/强制弃牌、升级、复活、出生断线夹具 | 每个窗口从服务当前投影继续；各客户端最终公开状态一致 |

每步先写失败的边界测试，再实现当前层，保留一个真实进程例子。首轮不同时接外网、账号与完整同步优化。接口名称可按实现调整，但身份不能从消息ActorSeat获取。

## 场景矩阵

| ID | 最小触发 | 应观察到的结果 |
|---|---|---|
| N01 | 四个不同凭证连接，第五个请求入局 | 四席唯一；超额请求失败，原局不变 |
| N02 | 向房间A发送房间B的MatchId；换成别人的席位字段 | wrong_match或解析拒绝；没有其他人的手牌/候选 |
| N03 | 四人暗选，第三人最后尚未确认 | 服务仍为Planning；各人只见自己的选择，第四份确认后才揭示 |
| N04 | 两条同revision选牌消息竞争 | 一条提交；另一条stale_revision，客户端保持原命令ID直至用户重新选择 |
| N05 | 服务已执行弃牌但回复在网络层丢失 | 续连后原ID重试返回duplicate，金币/弃牌/事件不重复 |
| N06 | 原ID修改目标或内容后重试 | command_id_conflict，不覆盖已接受记录 |
| N07 | 防御前断线；另一个席位尝试防御 | 只有原防御者续连后得到其候选；他人请求无效 |
| N08 | 飞斧支付成本后断线，再遭反射强制弃牌 | 原成本保留；第二次选择独立；空手/跳过各遵守原规则 |
| N09 | 两人同时升级，一人掉线，另一人完成 | 原选择者的候选不泄露；完成者不再显示候选；掉线者恢复后继续 |
| N10 | 英雄待复活或被占出生尚未选格时续连 | 唯一选择者拿到合法格；完成后父行动/轮末继续一次 |
| N11 | 同席新连接认证成功后，旧连接再发消息 | 旧代次被拒；不发生两个并行操作者 |
| N12 | 客户端晚收到旧Snapshot或旧Result | 画面revision不回退；仍核对CommandId，不重播旧奖励 |
| N13 | 中途服务器网络适配断开，核心仍运行 | 客户端显示断线并禁用确认；不会把本地点击作为已成功 |
| N14 | 发送null、未知Kind、重复JSON键、数值枚举、缺失参数或超限帧 | 输入边界拒绝，规则层无部分执行，服务继续处理合法连接 |
| N15 | 内容哈希或WireVersion/规则能力不匹配 | 建连阶段给出明确错误，尚未派发任何私有Snapshot |
| N16 | 四个实际窗口完成一轮，包括一次Pending续连 | 四人公开轮回合/单位/水晶一致；本人手牌分别正确；服务保存可用现有Restore核验 |

N04的“保留原ID”仅用于检查先前提交是否已成功；收到明确stale_revision后，若用户依据新状态重新发起操作，使用新ID。不得把新revision偷偷写回旧ID，造成命令内容冲突。

## 证据格式与退出条件

每次运行保存唯一编号、源提交、构建输入/程序哈希、四客户端及服务进程标识、消息方向/种类/CommandId/revision、错误码和用例结果。凭证、完整私有消息正文不写公共汇总；需要隐私断言时用测试进程内的独立断言，并记录检查名称及通过/失败。

网络自动测试与核心场景分开计数；实际可见四窗口证据与无窗口传输证据分开报告。丢包/断线注入只作用本测试连接，不修改系统防火墙或其他程序。测试结束关闭自己启动且路径核验通过的进程，保留失败现场文件。

N01—N16通过后，可将NET-01标为完成；NET-02的外网完整对局、Host退出与迁移、生产身份、服务崩溃恢复、观战和全部牌联动仍独立待办。若其中一项需延期，明确写出影响，不能以“网络大致可用”替代矩阵结果。
