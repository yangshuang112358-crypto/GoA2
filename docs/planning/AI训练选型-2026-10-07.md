# 训练选型核对

本批没有安装训练库、没有训练模型。2026-10-07 本机 base Python 3.13.13 与现存 markdown-mas-tutorial 环境均未装 torch、gymnasium、stable_baselines3、sb3_contrib。驱动471.51报告CUDA11.4；这不是已安装CUDA工具链或现代PyTorch兼容性证明。短GPU学习验证条件不满足，不更改驱动、不使用云或模型API。

## 核对后的候选

1. [SB3-Contrib MaskablePPO 官方文档](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html)：支持离散动作、Dict观察、无效动作过滤；不支持循环策略，Dict动作不支持。子进程环境须自己实现 action_masks，评测须使用对应 maskable 回调/评测器。不能把 RecurrentPPO 直接拼成带记忆的 MaskablePPO。
2. [RLlib MultiAgentEnv 官方文档](https://docs.ray.io/en/latest/rllib/multi-agent-envs.html)：可表示轮流、同时及混合行动；通过返回观察的 agent 集合表达谁下一步行动。适合真实决策者不断切换，但仍需自定义候选编码、遮罩与策略映射；并不自动解决本项目的暗选隐私和跨席位回报。

阶段二优先尝试独立 Python 环境中的前馈 MaskablePPO，先固定一个学习席位/团队，其他席位使用被冻结的基线/历史对手。C#持有规则，Python只做张量编码、训练及进程通信。训练器不能直接读取本批的权威存档目录。需要双向命令协议及终局/截断标记后再安装并锁定版本；本批没有声称通信层或库组合已验证。

可变候选不能让网络把“第17个动作”记成永恒语义。优先为每个候选编码命令类别、卡编号、目标实体、位置、模式，用共享打分网络对合法候选归一化。若为了初试使用固定最大容量，先扫描本批候选最大值并留余量；任何超限直接报错保存现场，绝不切掉合法项。SB3原生固定输出与这种候选打分并非直接匹配，须实现并验证自定义策略；可先用显式稳定动作词表做较小固定局面验证。

在前馈版本学到基本目标前，不引入记忆网络。需要记忆时先把公开历史编码为结构化特征，或者单独验证支持mask的循环策略。暗选每席分别保存隐藏状态，不能把前一个席位的本次动作塞入下一席位隐状态。团队共用参数不等于共用私有信息。

## 训练合同

主要目标为团队胜负。第一版只用真正终局 ±1，截断不是平局或失败；有价值函数时截断须按可引导终止处理，不能把它当真正终止。随后若加入中间奖励，先做刷金币、无效来回移动、拖延终局、送队友的对抗测试。优先采用与团队优势相关的有界势能差，并检验它不改变获胜目标。

初次规模：单worker验证；实测允许后试2，再试4；保留至少4个逻辑线程与约4GiB可用内存供交互，避免一次创建16个环境。显存目标先控制在4GiB以内，小MLP或候选打分网络，分别记录采样、编码、更新耗时；8GB显存并不保证GPU比CPU快。

模型/检查点除权重外必须保存源提交、规则/内容哈希、观察/动作合同、超参数、种子流、对手快照ID、评测摘要和训练游标。ArtifactContract先实现严格规则程序集/内容/格式核对；有差异拒绝加载，需要明确迁移或重新训练并重新评测。难度以后通过历史快照、搜索预算与可解释打法调整，不能读取未揭示选择。

固定局面、固定阵容课程与正式完整对局独立统计；最终评测保留不参与训练的种子和换边，比较随机、简单、历史对手池，不把击败随机称为“会玩”。后续1/8/24小时预算见第一阶段实测验收；需用户确认后安排，本批不会自动开始。
