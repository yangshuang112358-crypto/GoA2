# 反击实施合同与执行帧接入

正式源：shargatha-00-反击，金色基础攻击3，先攻11，次移1、次防2，无被动/范围图标。

“选择与你相邻的一个单位为目标。攻击后：此回合，当你因任何原因丢弃一张卡牌后，如果可行，执行你弃牌堆中一张攻击牌的主要行动。（优先执行完导致弃牌的行动。）”

## 已确定规则

- 先正常选择相邻合法敌方单位、攻击及防御，攻击后建立本回合弃牌触发；无目标停止、次要移动和次要防御均不建立效果。
- D-044：每弃一张分别累计，等整个致弃攻击行动（含攻击后移动/推动及后续选择）结束再执行。不能在弃牌函数内递归发起攻击，不能按同一行动去重为一次。
- 每次实际执行时重新查询本人弃牌堆中可执行的攻击牌及其合法目标。没有可执行牌自动消耗该次触发；有候选由夏尔加萨本人选择，不提供主动跳过。执行的是该牌完整主要行动，不是固定伤害或金牌复刻。
- 被选牌仍留弃牌堆；不改变本回合揭示卡、先攻或四个出牌槽。不能替换为次要/快速行动。同一弃牌可在后续触发再次选中，只要届时仍合法。
- 每次反击是独立行动，应触发幻化行动前，并支持所执行牌的重复、防御响应、兵线推进与等待。新发生弃牌记录到其真正的致弃行动实例，等待该实例结束；旧等待项不能在子行动完成时抢先当作子行动触发。
- 来源取回/被替换、英雄击败和回合结束使用既有持续生命周期；英雄不在场不能执行反击。胜利清除所有等待/父帧，不得恢复至进行中的对局。

## 实施边界（引擎63）

1. 为新引擎的主要行动、攻击重复和调试攻击保存唯一实例ID。统一记录真实弃牌的入口，保存触发来源、拥有者、弃牌原因、致弃实例ID；交换牌区不是弃牌。事件仅做审计，不解析事件文字执行规则。
2. 加可序列化的待触发队列和父行动帧；当前Execution只保存栈顶，挂起Execution由父帧独占，避免两份可变副本。牌选择前保存父席位、阶段和恢复边界。
3. 在完整攻击后步骤/防御后续/小兵回归完成后、进入下一次重复之前处理对应实例的触发；最终完成也在推进先攻之前处理。子反击结束后恢复对应父边界一次。
4. 弃牌堆执行的攻击目标/距离从Execution.CardId取，不要求该牌PlayedUnresolved；所有普通出牌入口仍保留原先限制。独立选择命令与私有候选投影，界面只提交核心给出的牌/目标。
5. 新字段默认省略以保留旧档原始字节；引擎升级条件检查队列/父帧；旧版本不开启新触发。存档深度和无限递归均不得靠静默丢触发规避。

## 必测差异

正常金牌激活；金牌攻击无目标/次要行动不激活；弃防御牌后等敌人攻击后移动；空候选与多牌选择；累积两次、同一弃牌可再用；黄蜂屏障反制中子反击再次弃牌；幻化行动前/横枪跃马重复；发动者被击败；重型击败出生选择/胜利；来源取回与回合结束；每种窗口保存重放、错误席位/重复命令、对手看不到未选择的弃牌牌名；旧62窗口保持字节。手工从敌方整次攻击前加载，不从半途弃牌窗口开始。
