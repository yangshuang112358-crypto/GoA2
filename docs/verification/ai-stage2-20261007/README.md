# 第二阶段短时学习证据

验收与启动见[短时学习验收](../AI短时学习验收-2026-10-07.md)。没有玩家级强度结论，也没有启动长训。

- cpu-smoke-01：两轮CPU PPO，含初始、001、002检查点及对应配置/更新/评测；共485学习步。
- cpu-resume-01：从002实际恢复后再训练172步，003检查点；恢复起点权重已由上一目录的002保存，此处保留其元数据而不重复二进制。
- gpu-smoke-01/02：两次GPU内存保留线停止的原始失败记录。01还暴露了现已修复的资源报告作用域错误；02完成一场推理，未执行PPO更新。
- model-replay：两轮PPO模型的391命令默认规则完整局；scenario/final-save属于权威证据，policy.jsonl.gz仅为学习席允许观察，spectator.jsonl.gz是独立公开观众事件。
- unity-model-replay：现有Unity Player原生验证日志、最终状态和构建载荷检查。无窗口，不代表画面/录像验收。
- profile-default/profile-life10-marks4：同种子211换边，独立规则内容包、统计和压缩完整存档/命令。每组2场均真正结束，后者不是默认模型已能泛化的证明。
- tests：最终9项C# TRX、6项Python输出，跨提交重建哈希和检查点合同核对。
- behavior.json：三个检查点在相同评测种子下的部分行为统计，不能代替团队胜负。
- resume-consistency.json：恢复后的整场允许输入/行动一致，初始CPU/GPU最终存档一致。
- profile-model-rejection.json：默认规则真实检查点对10生命4标记内容明确拒绝加载。
- profile-outcomes.json：四场配置对照的胜利原因、终局生命/标记和等级；有一场正式达到8级且装备紫卡，非全部紫卡覆盖。
- sha256.json：上述捕获文件逐字哈希（不包含本README与清单自身）。证据目录禁用Git换行转换，避免破坏原始哈希。

全部原始逐步日志与失败现场仍保留在本工作树artifacts/ai-training，未通过换种子或覆盖输出隐藏失败。读取训练数据只用允许观察文件；不能将权威存档送入策略。加载这些检查点必须使用配套构建选项与相同合同，旧观察格式和规则变体需明确迁移。
