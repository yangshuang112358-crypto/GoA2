# 卡牌关键词展示调研与建议

调研日期：2026-09-12。后续状态：用户批准后，推荐方案已在BATCH-04的KW-01落地，证据见[工作记录](../verification/BATCH-04工作记录.md)。正文保留原调研依据与建议，文中“尚未”描述的是调研时点。当前采用少量颜色＋加粗＋词条解释，不增加默认方括号或空格；正式原文与牌效保持独立。

## 市场已有做法与可借鉴部分

| 产品/规范 | 查到的具体依据 | 对Goa2V1的启发 |
|---|---|---|
| Legends of Runeterra（符文之地传说） | Riot官方Data Dragon将带格式描述、纯文本描述、关键词及关键词引用分开。当前set1数据中的Yasuo把Stun与Recall标为关键词链接，Stun还带独立图标；纯文本字段保留正常句子 | 为术语建立统一词典和样式，图标可辅助识别；显示标记与正式原文分离 |
| Magic: The Gathering（万智牌） | 官方设计文章说明关键词是机制的稳定简称；提醒文字帮助新手，斜体使熟悉规则的人容易略过。另一篇说明ability word用于归类，不能与有实际规则定义的keyword混淆 | 区分“规则术语”“时点标签”“解释文字”；补充解释不应盖过正式效果，不给所有高亮词凭空添加新规则定义 |
| W3C文字呈现原则 | 颜色不应成为表达信息的唯一方式 | 同时保留完整词语和加粗，即使看不清颜色也能理解行动及条件 |

来源：[Riot官方开发文档](https://developer.riotgames.com/docs/lor#data-dragon)、[Riot当前set1数据](https://dd.b.pvp.net/latest/set1/en_us/data/set1-en_us.json)、[万智牌Keyword to the Wise](https://magic.wizards.com/en/news/making-magic/keyword-wise-2003-05-19)、[万智牌Ability Word To Your Mother](https://magic.wizards.com/en/news/making-magic/ability-word-your-mother-2008-07-28)、[W3C Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html)。

证据范围：Riot部分核查官方数据结构及实际字段，未将其等同于最新客户端的逐像素界面测试；两篇万智牌文章分别发表于2003年、2008年，作为已采用过的设计方法依据，不据此声称2026年所有牌面排版完全一致。这里不宣称做了全市场普查。

## 推荐的第一版

下表的颜色与符号分配是本项目建议，不是上述产品的原样配色。颜色值用于当前深色背景的设计讨论，正式实施时再实测对比度及108张牌的排版。

| 信息 | 建议样式 | 示例/说明 |
|---|---|---|
| 动作与机制 | 暖金色`#F6D278`＋加粗 | 攻击、移动、防御、抵挡、丢弃、放置、推动、取回；同类统一，先不用六套动作色 |
| 时点与持续期 | 浅青色`#84D8E7`＋加粗 | 攻击前、攻击后、本回合、本轮、下一回合；必须完整匹配，不能把“下一回合”只标成“回合” |
| 决定合法性的限制 | 高亮白色＋加粗 | 可、必须、否则、非、不能、最多、除外、如果可行；否定词与其对象一起显示，例如“非远程攻击” |
| 被击败后果 | 柔红色`#FF9B94`＋加粗 | 被击败；完整保留文字，不能仅靠红色表达后果 |
| 数值与单位 | 随对应短语一起强调 | “丢弃一张卡牌”“最多2格”；数值与单位尽量不在行末拆开 |
| 队伍与卡牌颜色 | 保留现有色条；正文写明敌方/友方 | 不把所有正文敌友词都改成队伍红蓝，避免与卡牌颜色、当前操控队伍混淆 |
| 已有被动加成 | 延续现有绿色`+数字` | 不重定义绿色加号的含义 |

不建议高亮“一个、然后、单位、英雄”等每个常见词。关键词密集的一句话中，首先保证动作、数量、限制和时点清楚；强调越多，扫读优势越小。

## 引号、括号、方括号、空格怎么使用

| 手段 | 建议 | 原因 |
|---|---|---|
| 中文引号`“”` | 用于正文中引用具体卡名，例如“近身还击” | 卡名与规则动作各有独立标记；不把普通术语都当引文 |
| 圆括号`（）` | 用于明确的补充解释，优先放在词条解释区 | 强制步骤、否定条件不能被排成可略读的注释；原文已有括号按原文保留 |
| 方括号`【】` | 可试用少量时点标题，例如`【攻击后】`，仅在原文确有该时点时提供 | 适合分段定位；若套在每个关键词两侧，会增加行宽和视觉干扰。首版作为可选方案，不默认添加 |
| 关键词首尾空格 | 不往正式中文句子里批量插入普通空格 | 会增加换行、影响检索和复制；需要间距时在展示层控制约2—4像素，且不得拆开否定词、数量和单位 |
| 行距与段落 | 完整卡面按句子/原有阶段分段，正文保持足够行距 | 优先使用现有完整卡面空间；小卡预览继续保留省略标识，不能以高亮代替缺失的规则内容 |

## 同一段原文的三种处理

使用现有近身还击原文示意排版；其新裁定独立记在[EFFECT-001](../planning/卡牌效果调整清单.md)，下面不代表程序已支持新选择。

- 保守方案：**抵挡**一次**非远程攻击**。攻击者**丢弃一张卡牌**，**否则被击败**。只加粗，改动与学习成本最低。
- 推荐方案：保持上述原句，动作词用暖金色、否定与“否则”用加粗白色、“被击败”用柔红色；支持查看术语解释。无需给每个词加符号。
- 标签方案：仅对确有“攻击前/攻击后”等原文时点的牌，追加对应时点标题，其余与推荐方案相同。近身还击这段没有这些字眼，因此不凭空加`【攻击后】`。

桌面可沿用悬停完整卡面；将来触屏操作建议以长按或明确“详情”入口查看完整卡面，再点术语打开解释。点术语应只解释，不能意外选择卡牌或确认行动；不要求手机用户依赖hover。

## 后续落地范围与验收

1. 确定统一术语表，明确显示名、分类、解释来源；解释只引用已确认规则，未决裁定不能自动补答案。
2. 在呈现层生成格式片段；`content/canonical`、纯文本检索、复制、存档和重放仍使用正式原文。先转义特殊字符，按最长完整术语匹配，避免“非远程攻击”“下一回合”等被拆错或重复嵌套格式。
3. 同一套片段覆盖手牌、揭示牌、升级候选、完整卡面和图鉴，不单独维护五份颜色规则。完整词条解释与小卡选牌动作分开处理。
4. 先用长文本、否定条件、复合时点和大量关键词的代表牌做对比样张，再检查108张牌在1600×1000、1280×800的完整卡面及预览。富文本改变测量结果后，重新验证换行、省略号、字形裁切与最小字号。
5. 验证去除样式后原文一致、深浅颜色下均可读、说明层不提交命令、不遮挡确认操作；本轮调研不计入已实现功能或测试通过数量。

结论建议：先采用推荐方案；括号和引号按用途少量使用，方括号时点标题可先出样张，中文正文不批量补首尾空格。
