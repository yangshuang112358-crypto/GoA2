# 行动链设计方案 · 2026-09-29

最新补充：同先攻由原“仅待定分组”调整为揭示后按决策币预排队色，战斗中仅更新未行动部分；凹槽悬浮币及摆动见[动态预排与草图](行动链动态预排与草图-2026-09-29.md)。新文档覆盖下文不预排队色、仅显示单一中央币的旧建议。两份均为设计，未实装。

状态：供用户审阅的设计方案，未改运行时代码，未制作资产。依据用户本次行动链参考图、最新裁定、当前 engine97 规则与本人投影；参考图中的技能名、伤害、响应方式不是本项目规则。

用户追加确认：响应板必须在回合进行中实际触发时动态插入，不能开局预插、不能预留空板；插入与同队顺序变更动画需要明显视觉张力。多人同先攻必须支持成组展示，不限定为两张对换。以下动效细节与时长仍是设计建议。

## 目标与已确认方向

替换当前左侧四张已揭示牌。视觉采用木质底板、古铜金属包边、左右双链悬挂、局部魔法连接。四块板从屏幕顶端垂直落入，不采用参考图向左侧斜着甩入的方式，不大幅倾斜。

四块主板代表本回合四张揭示牌的行动机会；插入板代表这些行动引起的响应或其他规则步骤。需要响应的英雄原本待执行的揭示牌不因此提前，也不能误显示为已经执行。基础攻击、次要移动、快速移动等实际执行内容需标出，不能只显示所揭示卡名让玩家误认正在执行其主要文字。

## 推荐结构：主行动顺序加因果树

主链回答“原本轮到谁”；缩进支链回答“为什么现在换了谁操作”。同一条链不能把发生时间、因果关系、未来先后混为一谈。

建议常态主板包含：英雄头像/名称、技能图标/名称、先攻、状态；不用一直放完整规则段落。进行中的板额外显示一行即时信息，例如“攻击 → 夏尔加萨”“等待夏尔加萨弃牌”。完整卡文仍由详情查看，不把微缩文字烧进贴图。

双链外轨维持整体悬挂；分支使用内侧短链、弯接点及缩进。插入响应时下方主板平稳下移，外轨延长，支链接通。视觉不必真的断开两条承重链、任由整串板倾倒。

推荐在1600宽画面中占约300—340像素；1280画面优先约280—300像素。尺寸是待原型验证的起点，不是已确认数值。主板约90—112高，响应板约64—80高。全部主板宽度一致，避免参考图随文本任意改变宽度。响应短板可以更窄；标题允许两行，不牺牲字体清晰度。

正常四块主板同时可见。响应增加时仅当前主板展开，已完成子步骤折为一行摘要，未执行主板保留短版。最多两级明显缩进，更深层使用固定宽度及“响应层级”提示，点击可展开完整结构；不限制真实规则深度、不删除记录。

需要滚动时仅滚行动链，鼠标离开链后滚轮继续控制地图。当前操作节点自动滚入可视区，但用户主动查看历史时暂停自动滚动，并提供“回到当前”。不使整串牌每次增项都重新从顶端掉落。

## 时序与规则映射

| 真实情况 | 行动链表现 | 禁止的误导 |
|---|---|---|
| A攻击B，B需要防御/弃牌 | A主板保持挂起，下面展开B响应；B原主板仍在待执行区 | 把B原揭示牌挪到A下面当防御牌 |
| 攻击前让另一英雄弃牌 | 在本次攻击实例的“攻击前”节点下记录；之后返回原目标攻击 | 将弃牌者当作原攻击目标，或跳过原攻击 |
| 防御前触发幻化/斗篷 | 防御下展开真实前置步骤，结束后返回防御 | 因为是紫卡就插到整个回合最前面 |
| 夏尔加萨反击累计 | 触发时标“等待当前攻击结束”；到引擎开放反击窗口才展开选择 | 把待触发显示为立即中断攻击 |
| 一次行动弃两张触发两次反击 | 两个独立触发节点，可摘要“待反击×2”；展开仍保留每个触发 | 合并为一次反击或提前展示未选攻击牌 |
| 惊涛骇浪、斗篷等重复 | 主板内列“首次”“重复一次”，每次有自己的目标和响应 | 新增一张第五主行动牌，或无视重复次数/不同目标 |
| 雷霆回旋镖连续触发 | 随实际规则逐次追加，过长时折叠已完成部分 | 用普通最多两次的展示模板截断真实链 |
| 多目标/多个弃牌对象 | 同父步骤下逐个列节点，突出当前需要决定的一项 | 把串行规则画成同时伤害或同时选择 |
| 潮汐之主引发兵战 | 基础技能后挂“可触发兵战”，实际选择后展开队长移除/推进/回归 | 站在非交战区时也预先显示可触发 |
| 一人成军终止兵战移除 | 兵战节点显示终止剩余移除/不推进，再按引擎恢复父流程 | 误把整个行动或整个轮末标成结束 |
| 中毒、石化、免疫等持续效果 | 首次产生/变化可留摘要，常驻内容放英雄状态 | 每帧动态重算就插入大量响应板 |
| 无合法目标/取消/拒绝/免疫 | 按实际结果显示跳过、未执行、拒绝支付或免疫 | 用统一“成功完成”掩盖不同后果 |
| 复活、轮末、升级 | 非四牌行动用独立阶段节点或原界面，不能硬挂到最后一张牌 | 把轮末兵战写成最后行动者发动的技能 |

示例（只示意层级，各步仅在规则实际出现时展示）：

```text
阿连 · 惊涛骇浪                         [执行中]
  ├─ 首次攻击 → B
  │   ├─ 攻击前：C弃牌 / 选择被击败     [当前响应]
  │   └─ B防御                         [尚未到达]
  └─ 是否重复                          [之后由规则开放]
B原本的揭示牌                          [待行动]
C原本的揭示牌                          [待行动]
D原本的揭示牌                          [待行动]
```

上例仅是设计说明的完整树，不是初始界面。揭示时只有四块主板，没有子板、空位或预告步骤；规则实际触发响应后才插入对应板块。示例中的B防御、重复机会不能在还未触发时出现。不保证每次都出现B防御或重复机会，实际以引擎为准。反击触发后才允许插入“待触发”节点，到对应完整行动实例结束时才成为当前节点。

## 同先攻与队长选择

1. 揭示后先攻高者在上。同值组加一条“同先攻·顺序待定”连接标记；组内暂按稳定席位排列但不标最终序号。
2. 同队需队长选择时，只有服务器给出的候选主板亮起金属扣环，提示对应队长选择。本人的有效选择才可点击；他人的预选不广播。
3. 确认后选中板解除两侧锁扣并明显前浮，借透视增大与阴影强调深度，沿旁侧短弧轨道越过同组板块进入组首；其余板稍后退、下移让位。落定时双链拉直、锁扣咬合、金属冲击与短促光脉冲同步。保持板面近乎水平，不用大幅倾斜或整串摇晃表达力量。若选择的本来就在组首，只做前浮/锁定，不做无意义换位。
4. 跨队同先攻先以规则决策币结果确定队伍；沿用棋盘中央已有翻币演出，只让结果对应候选板同步发光，不另外计算/翻一次币。
5. 每执行完一张再依据权威状态处理剩余冲突，不一次性排死整个同先攻组。

这里的先攻值、候选、选择者和币翻面都由规则提供。普通回合开始的主板排序与队长决定先后必须区分。

### 三张、四张及未来更多同先攻

- 仍使用一列主板，组外两条粗链包住同先攻集合，侧面仅标“先攻11 · 4人 · 顺序待定”等短签。不铺成多列、不把四张互相交叉连线。
- 组内位置仅是稳定展示位置，不标1/2/3/4行动序号；只有已被规则选中的当前行动卡解除组扣，进入本组最上方的执行位置。已完成卡压成摘要，避免占据全部高度。
- 跨队时，决策币先确定本次获得先手的队伍；只点亮该队合法候选，队长选择其中一人。其余牌不因当前币色提前整体排队。
- 例：四人均先攻11、币为蓝。蓝队长选一张，该张前浮抽出、币转红；执行完成后，剩余三张仍为待定组。下一次由红方获得候选，再按规则处理。保留原先攻逐次裁决，不能一次决定“蓝蓝红红”。
- 当前四席每队两人，所以“同队三人以上”尚不存在；若未来扩展人数，组仍可容纳更多候选，选中一张抽出，剩余板稳定挪位。UI方案可预留N张，不能因此宣称核心已支持六人或更多联机。
- 组高超出可用空间时压缩已完成项，待定项仍保留头像、技能名和先攻；必要时局部滚动，当前候选和队长选择提示保持可见。

## 动画与信息状态（建议值）

- 揭示：主板从顶端竖直落入，约0.45—0.65秒，板间错开0.06—0.10秒；左右链同步拉直，小幅垂直回弹。板倾斜控制在约0—2度；镜头不跟着抖。
- 插入（建议总长0.55—0.75秒）：触发后双链先绷紧约0.08秒，节点蓄光；上下板分开并拉出空间约0.16秒；响应板从连接点方向带明显前后深度切入约0.18秒；两侧锁扣连接、短促闪光与粒子、链条弹一下后落定约0.18秒。只新增实际需要的链节，不能先出现空槽等待未来响应。
- 换序（建议总长0.65—0.85秒）：候选被规则确认后解扣、前浮、越过其他同组板、归位并拉紧双链。张力主要来自前后景层次、先蓄力后加速的节奏、金属音效与局部光，不靠板面大幅旋转。视觉重排不代表任何玩家可自由拖拽改变先攻。
- 连续响应时保留每次插入辨识度，但不积累无限长演出等待；下一合法输入可在节点稳定可点击时开放，装饰尾光可继续。服务端结算从不等待粒子结束，迟到/密集更新允许压缩装饰演出并收敛到最新状态。
- 状态：待行动为暗铜，当前操作用轮廓脉动及明确文字，挂起为呼吸光+“等待响应”，待触发用空心节点+原因，完成为静止并稍暗，跳过/取消有独立文字。
- 颜色职责：队伍只在头像环/小队色条；卡色在图标边框；连接魔法光用单独强调色。不要把所有响应做蓝色，否则容易误认蓝队。不能仅靠颜色区分状态。
- 结算后短暂停留，再将完成的子树压成摘要；下一个真正操作节点可立即读取，不等待长动画才允许规则输入。遇到更新密集、快进或重连直接收敛到最新稳定布局。
- 揭示在所有玩家确认后才播放；暗选预览、取消等不会提前生成公开主链。远端只演出已公开发生的选择与结果。
- 左侧是阅读信息，镜头继续由既有跟随机制管理：关闭跟随时不因面板动画强制移动镜头，不插入第二套争抢镜头的系统。

## 数据与实现边界

当前 GameView 有公开事件、单个 PendingChoice、Attack、先攻候选等，可做当前响应的简单插板。核心还有 ActionInstanceId、BeforeActionFrame、DiscardReactionFrames 等恢复信息，但没有把完整公开父子链统一提供给UI。GameEvent没有统一的 ParentActionId / RootActionId。

因此可靠的深层树不能只靠解析 Detail 文本或比较英雄名猜测。建议先增加只读的公开 ActionChainView（暂名），稳定节点ID、父节点ID、根行动ID、发起者、实际选择者、已公开来源牌、当前状态、排序及已提交目标；在 Application 层从权威状态/事件构建，经本人投影脱敏。不可把内部完整执行栈直接发给每个客户端。

UI单独维护入场、展开、折叠进度，以 MatchId/Revision/EventSequence/NodeId 去重。重连使用公开链快照恢复，初次连接不重演此前所有坠落与弃牌。多客户端知道相同已提交结构，但不要求装饰粒子逐帧相同。

保存/旧档兼容、事件字段及网络DTO是否扩展，需要实施时做接口审查。新字段若改变对局持久化/事件序列必须按已有版本兼容流程处理；本方案不借展示需求更改结算顺序。深层树属于适度的数据接口改造，不是单纯修改USS。

## 美术路线

参考图可作为古铜金属、木纹、倒角与链节的方向，但该图为综合概念效果，不能直接当运行时成品。推荐先以当前绘制体系验证排版及一条真实响应链，再做一块主板/一块子板的最终材质样板。

按用户已拟定方向，Blender制作链节、包边、连接扣和模型/法线；Unity管理布局、灯光/材质、插入动画和少量粒子。文字、状态、动态数值单独实时绘制。可采用烘焙材质加局部3D高光的混合方案，减少UI Toolkit中同时放大量3D对象的成本。最终是否使用独立UI相机/RenderTexture，在样板性能和清晰度测试后决定。

不建议以运行时刚体真实碰撞计算整串链条：稳定位置和可读性比随机物理更重要。使用确定目标位置的骨骼/关键帧/程序弹簧，仍能做重量感。画面品质主要依赖资产、灯光、材质和动效调校，不能承诺仅换思考档位就达到参考图品质。

## 推荐分步验收

1. 确认一块主板与响应板静态样板：大小、文字层级、古铜/木纹、双链与卡色/队色。
2. 实现四板垂落、当前步骤、普通攻击/防御/弃牌插入及完成折叠；在1280和1600下验证战场占用。
3. 补齐公开因果投影；复验紫卡防御前置、反击等待与累计、重复攻击、兵战和先攻冲突。
4. 四客户端验证权限、暗选/预选隐私、断线恢复与重复包不重播；最终材质/音效与降动态模式再收尾。

验收以真实规则场景为准，不只制作一段无法交互的演示。沿用“已实现部分移除旧入口，尚未迁移部分保留”的用户约定；行动链若承担队长选择，则删除原窗口对应重复入口，但保留未迁移决策。
