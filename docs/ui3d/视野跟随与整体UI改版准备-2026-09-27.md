## 下文为实施前建议记录（与上文冲突时以上文为准）

## 最新方向与既有要求

用户目标：空格切换视野跟随，底部上浮提示“视野跟随模式：开/关”，停留1秒后淡出；交互体验参考炉石传说，战场建模方向参考英雄联盟；减少四周窗口对战场阅读的影响。遇到大改动或与既有要求冲突，先说明影响和替代方案。

保留既有大字号、完整卡牌阅读入口、已揭示牌持续可查、先攻排序、队伍/牌色区分、四个出牌点与紫卡标识、弃牌颜色记录、按轮历史记录和测试入口。减少常驻内容与面板尺寸，不通过普遍缩小文字解决空间问题。

## 核对的实际现状

- 已有Unity 2.5D棋盘，正交相机、滚轮缩放、中/右键拖动、Q/E十二档平滑旋转、Home全图和2D回退。无需更换引擎或重做规则核心。
- GameScreen.Layout.cs中空格执行confirmAction；GameScreen.cs还有阻止空格触发UI Toolkit默认按钮的事件拦截。新增开关必须统一处理两处，防止同一按键既切视野又提交行动。
- BuildLayout强制最低1280×1000；样式叠加后左栏300、右栏380，手牌340高，揭示区也占较大高度。旧engine79的1280×800全展开截图已能观察到地图被挤压。此次查看的是历史截图及当前代码，没有生成或冒称engine97的新截图。
- BattlefieldSurface.FocusAt会强制Zoom=3，不能原样用于每次跟随；应提供保留Zoom/Yaw的相机目标更新。
- GameScreen.Render清空根节点，棋盘元素重建会销毁场景；现有旋转/缩放状态保存在外部Board3DViewport。跟随状态和弹窗计时也必须跨Render保留，不能在重绘时重置。

## 下一步：视野跟随设计

### 已明确的行为

1. 空格按下一次切换开/关，长按不重复切换。文案严格为“视野跟随模式：开”或“视野跟随模式：关”。这是镜头行为，不是战争迷雾或游戏可见性规则。
2. 非阻塞提示从屏幕底部安全区上浮，避开手牌/操作条；建议上浮淡入0.18秒、完全显示1秒、淡出0.25秒。这里的停留不是鼠标悬停触发。提示不抢焦点、不拦截地图点击、不写规则日志。
3. 连续切换只显示一个最新提示，并重新计时；Render或窗口尺寸变化不使旧文案复活。卡牌阅读浮层、输入框和其他模态界面优先处理各自输入。
4. 新要求优先于旧空格确认：建议确认改为Enter及小键盘Enter，屏幕确认按钮保留。下一步同时修改快捷键说明及相关验证，确保UI Toolkit默认按钮事件与自定义快捷键不会双重提交。
5. 镜头平滑移动，建议0.2—0.3秒过渡，使用独立于规则的时间；保留用户缩放和旋转。镜头移动不会改变行动身份、清空选中卡牌、自动确认、切换玩家手牌或增加对局Revision。
6. 英雄被击败/等待复活时保留最后合法视角；重新出现在本人投影后再继续跟随。无棋盘的升级/菜单阶段不追踪，返回棋盘后恢复。不可回到(0,0)、锁到其他玩家或读取隐藏信息。

### 仍待选择的偏好（非规则裁定）

已异步询问跟随目标：A当前操作英雄（1234切换时跟随）；B当前行动/响应英雄（自动追踪全场）。尚未收到答复，本设计暂按A准备。用户随后答复优先，不把本假设登记为用户裁定。

A的含义：只对当前本地所选席位的英雄定位；其他人进入防御/弃牌窗口不会擅自切换观察身份。联网后只能根据本人会话投影处理，不能调用SwitchSeat以改变身份。若选择B，只允许改变相机目标，仍不得自动切换手牌或认证席位。

建议首版默认关闭，保留现有开局视角；空格开启后开始跟随。用户另有偏好再调整。

建议手动拖动或Home全图时关闭跟随，并显示同样的“关”提示，避免镜头立即拉回；滚轮和Q/E继续可用。跟随时滚轮以跟随目标为缩放中心，关闭后继续现有鼠标位置缩放。以上为设计建议，尚未执行。

### 改动边界与验收

负责人为本主对话，单线实施。最小接线范围：GameScreen的输入/提示层、Board3DViewport状态、BattlefieldSurface相机焦点；必要时适配HexBoard的2D回退。不改core、canonical、网络协议或游戏存档。偏好如需保存仅进入本地视图设置。

建议将跟随控制与Toast呈现拆为独立展示组件；事件传入最新GameView和当前观察席位，组件只输出镜头目标。提示状态保存在重建根节点之外，或由跨Render的计时状态重建剩余动画。

验收：开/关及快速连按；文本框和模态输入；空格不提交、Enter只提交一次；英雄切换/移动/放置/击败复活；缩放/旋转不被重置；拖动/全图优先；窗口重建及两种分辨率下计时/位置正确；2D回退行为明确；以上镜头操作均不改变核心保存和Revision。实际键鼠与图形检查单独记录，不用单测替代。

## 四周窗口的推荐去向

默认画面建议：顶部窄状态/先攻带，左侧窄头像带，中间大棋盘，底部手牌和当前行动条；右侧默认只留详情/记录入口。面板采用叠加展开，尽量不挤压棋盘。默认行动视图以战场可阅读面积约占窗口65%—75%为设计目标，需用实际1280×800和1600×1000样板验证。

| 当前内容 | 常驻形式 | 可进入战场的部分 | 完整信息入口 |
|---|---|---|---|
| 左侧英雄资料 | 窄头像带，当前角色强调；出牌四点和紫卡标识保留 | 棋子上的行动标记、少量状态图标；悬停/选中显示完整英雄名 | 点击头像展开金币、升级、被动来源及完整弃牌颜色记录 |
| 顶部已揭示牌 | 持续显示紧凑先攻顺序条，保留已揭示牌身份、牌色及队色 | 当前行动者脚底光圈；必要时显示正在执行的牌标记 | 悬停/点击放大完整卡牌；不因镜头移走就丢失整轮公开信息 |
| 右侧行动/响应 | 底部情境操作条，仅列当前可执行选项 | 合法目标描边、移动路径、技能范围、选中目标；攻击时显示简洁攻防摘要 | 长说明与来源计算展开；防御/弃牌选择继续提供明确确认及拒绝选项 |
| 底部手牌 | 浅扇形/轻重叠手牌，悬停抬起；可切完整阅读模式 | 选卡后的目标连线/高亮 | 全文浮层或固定阅读面板，保留关键词、附注与数值加成 |
| 最近记录/全部记录 | 角落记录按钮，短暂显示关键事件 | 击败、推动、金币变化等简短反馈 | 按轮分页的完整日志抽屉 |
| 地区、出生点、战线、水晶 | 地图标识加顶部简要比分 | 格面纹样、阵营旗帜、水晶模型、当前交战区边界 | 悬停说明；不让装饰与可走格/实际墙混淆 |
| 调试、保存、图鉴、设置 | 工具菜单/可收起抽屉 | 不常驻战场 | 功能入口完整保留，手工用例说明继续可查 |

不把整张卡牌描述、所有历史记录、全部英雄被动数值同时挂在模型上；这只会把四个大窗口变成满屏小窗口。棋盘主要回答“谁在行动、能选哪里、这里有什么限制”。屏幕固定UI负责手牌、全局顺序及需要精确阅读的说明。英雄没有通用血量条机制，不为模仿LOL外观擅自添加血量表现。

## 风格准备与工作量判断

视觉方向建议为风格化奇幻战棋：石质棋盘/城墙、统一的金属或符文卡框、清晰英雄剪影、低干扰地表、明确阵营底座。炉石方向具体转化为卡牌抬起、聚焦放大、选中反馈、目标指示、短促出牌/响应动画；这是本项目建议，并非复制其界面资产或引入其规则。

战场参考LOL的轮廓辨识和信息层级，维持俯视可读性。Riot官方将清晰表达玩法、保持信息重要性层级及降低视觉噪声列为目标；据此，本项目优先让合法格、目标和行动反馈比装饰更醒目：[Clarity in League](https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/)。用户提出的炉石参考入口：[Hearthstone官网](https://hearthstone.blizzard.com/en-us)。此处是风格方向，不是最终美术稿或资产清单。

| 工作 | 判断 | 建议实施方式 |
|---|---|---|
| 跟随开关、Toast | 小到中等；现有相机可复用 | 先独立完成，覆盖输入冲突和Render重建 |
| 取消1000高的强制外层、战场优先布局 | 中等，涉及布局而非规则 | 做响应式分区与抽屉；不全局缩小文字 |
| 卡牌悬停抬起、放大与新卡框 | 中等 | 复用现有完整阅读、CardDisplay和CardTextMarkup；保留最新牌文接线 |
| 炉石式拖牌、目标连线、多段动画 | 中到大；会影响提交时点和多步选择 | 先保留点击操作，再增加等价拖动入口；动画消费事件，不驱动规则。通用行动撤回仍按旧待办暂缓，不借UI改版顺手实施 |
| LOL式完整战场和英雄模型 | 大，美术资产/绑定/动画/材质/性能占主要工作 | 先做一小块战场、一名英雄和三类小兵样板，验证阅读后扩展；不承诺换一套贴图即可达到完整商业美术质量 |
| 高墙/高英雄的遮挡 | 与此前“墙增高三倍、英雄为墙两倍”要求有关 | 保留当前高度，先考虑近处遮挡淡化、轮廓提示与标签避让。若样板仍不可读，再提出调整比例，由用户选择 |
| 持续动画和大量新模型 | 现有Render会重建场景，需局部架构调整 | 后续将棋盘对象按UnitId增量更新并复用资源；不是第一步跟随的前置条件 |

没有必要现在切换到其他引擎。大改动应先展示布局或一个战场样板，明确影响的旧需求；确认视觉方向后逐步扩大资产范围。

## 建议实施顺序

1. 下一步仅完成视野跟随、Toast、空格/Enter分工及对应验收。
2. 战场优先的响应式布局与右侧抽屉；保持现有卡牌和规则操作完整可达。
3. 统一卡牌尺寸/阅读方式/反馈动效，确认卡牌与棋盘的视觉层级。
4. 制作战场美术样板，核对墙遮挡、英雄辨识、队伍与牌色的区分。
5. 验证后扩展全场景和单位；最后增加更丰富的拖动及演出。
