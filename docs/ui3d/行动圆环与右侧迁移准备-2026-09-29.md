## 返回与规则提交的边界

现有 BeginPrimary 点击即提交命令，并可能立刻触发前置效果。普通无前置的次要/快速移动目前可仅改变本地 moveMode，但具备紫卡前置时也会提交命令。故不能仅给所有 Pending 添加“撤销”按钮。

建议区分三种行为：

1. 本地预选：点行动、浏览合法格、换目标、取消未确认落点。只更新本地 UI，不发网络预选，不改变规则事件；返回箭头可回到行动圆环。
2. 第一次实际提交：点勾后由核心重新验证权限、阶段、合法目标和版本；提交成功即关闭该返回路径。点击后到结果回包前锁定重复确认；重连沿用原命令 ID。
3. 多阶段卡牌：每一个已确认的弃牌、移动、前置能力或对手响应都是既成事实。后续返回只能清除当前未提交选择，不得抹去前面已发生的效果。跳过当前可选步骤是规则命令，不是 UI 返回。

具体冲突例：投掷飞斧先弃猛攻获得攻击距离，再选择目标。若此时返回并改用次要移动，既不能保留免费弃牌/触发收益，又不能把已经公开的弃牌与反击触发抹掉。幻化在行动前迫使敌方弃牌、斗篷与匕首先移动也有同类问题。建议先确认“启动并执行前置流程”，之后只能在当前未确认步骤内改选，不再返回最初行动类型。此例外需向用户说明，尚未获得新的回滚裁定。

无前置攻击/移动需要核心提供只读合法预览，不能由 UI 重写卡牌规则；现有 AttackTargets 等投影多在提交 BeginPrimary 后才存在。实施时先明确预览接口和原子提交边界，再接圆环。暂时无合法目标也要允许查看原因并返回，不能照旧点下去立刻结束。

推荐箭头使用“返回选择”而非“撤销已执行行动”；无可回退的未提交选择时隐藏。符号勾旁应有目标轮廓及选中路径，以免被技能环遮挡或误认为英雄可点击部件。Enter 触发同一确认；Space 仍只切换跟随。

## 左侧占用的建议（待用户取舍）

当前宽度约屏幕31%，上限500px；1600宽屏接近三分之一。完整描述、数值、身份、升级被动、结果都常驻使卡牌很高。仅缩宽会增加换行，纵向问题更严重；不建议直接把全部文字缩小。

推荐紧凑模式：

- 常态主轨道宽约300–340px（1600基准），占约19–21%。
- 每块平时保留真实卡名、英雄/队伍、卡色、核心数值、动作角色图标及一行结果；完整卡牌内容保存在展开态，悬停或右键读全文，不编造摘要替换正式牌文。
- 当前行动与正在处理的响应优先展开；结束的兄弟响应和未行动主牌折为短石板，减少滚动距离。鼠标浏览期间不自动收回，只有下一主行动开始才重新置顶。
- 层级每层缩进约16px，连接线持续表示父子关系。深层达到有限缩进后保持卡宽，用祖先路径/高亮补足，避免越深文字越窄。
- 响应插入仍在实际提交发生时播放；一次性发出多节点也保留完整记录，动画排队有时长上限，不阻挡输入。
- 主卡凹槽、仅未行动同先攻组币、行动后脱组、反击新增一级及局部滚轮规则继续保持。

这会改变此前“每张石板始终展示完整卡牌内容”的方案，应由用户选择；本批未擅自折叠。若坚持所有卡全文常驻，可先去掉重复身份标签/基础牌等级/“升级被动无”，收紧内边距，宽度只减至380–400px；收益有限，但不缩字、不隐藏牌文。

## 建议实施顺序与验收

1. 明确前置效果的提交边界；行动圆环、普通移动/攻击的本地预选、地图勾与返回，先接单一入口。
2. 接复杂牌内多步决策、对方响应、取回/换牌/反击；移除对应已迁移的右侧交互，未迁移保留可查。
3. 接轮末、升级、队长任务与部署/重生，确保整轮操作不必打开右侧。
4. 用户选定紧凑模式后再改左侧，录同一三级场景对比。

验收至少包括：确认前返回无Revision变化；确认后不可回滚；前置弃牌/移动/紫卡已生效后不能返回行动类型；无目标不会消费行动；网络本人权限和私有预选；断线/重连不重放提交；两种分辨率的格上勾不遮挡目标；整轮包括升级、小兵任务可不打开右侧；三级与更深连锁仍可读且滚轮不误缩放地图。
