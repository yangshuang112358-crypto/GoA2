# ADR-005：四身份联网切片的边界

日期：2026-09-10。状态：proposed，设计已整理，尚未实现网络服务或客户端。关联NET-01；不改变本批热座程序、卡状态或存档版本。

## 背景

GameSession已经把连接身份参数与Command.ActorSeat分开，并按席位生成GameView。现在的Unity界面直接持有完整本地会话，1—4只切换热座控制者。联网不能把这个按钮当认证，也不能把ExportSave、AcceptedCommands或所有人的完整GameView打包广播。

现有执行入口有锁，但一个房间的一次操作还包含持久化与向四人发结果。网络适配需要在房间边界串行处理这些步骤，不能依靠“Execute线程安全”推导“消息与落盘顺序一定一致”。

## 建议方案

NET-01先做同机、回环地址上的一个权威服务和四个独立客户端进程。服务不占玩家席位；总席位仍为0—3，UI显示1—4。之后若采用玩家Host，Host只是其中一个已认证客户端，同时承载服务，总人数仍为4。专服、外网发现、穿透、账号、匹配、观战、Host迁移均不在首个切片内。

服务管理房间、连接与席位绑定，私有会话只在服务端。客户端收到的是自己的投影。网络适配单独依赖Application/Domain，传输库留在适配工程；Unity和纯规则层均不引入服务器SDK。具体库在实施时根据锁定运行时验证后确定，此设计不假称已经选定或测试了库版本。

第一份连接入口只接受当前引擎的新建普通确认对局，Sandbox=false、QuickSelection=false。每席使用不同的房间凭证绑定，凭证不由ActorSeat、昵称或热座选择推导。客户端请求不携带ActorSeat，由服务从连接绑定生成Command.ActorSeat并传给Execute。是否续连、替换同席旧连接以及凭证是否有效，都先于读取私有投影处理。

未认证连接拿不到对局投影，也不能通过输入其他席位号获取候选。NET-01只承诺服务仍存活时的断线续连；服务崩溃后的身份恢复和落盘承诺另设门槛，不用本地全信息存档伪装重连令牌。

## 消息与顺序

网络封套使用独立WireVersion，与GameState.CurrentProtocol、EngineVersion、ContentHash分开核验。首批用具名字符串消息和严格字段集合；不直接反序列化客户端提供的任意.NET类型，不把缺失的Kind默认成ChooseHero。

| 消息 | 方向与必要内容 | 行为 |
|---|---|---|
| Hello | 客户端→服务：WireVersion、内容/规则/引擎能力、房间凭证 | 验证连接，绑定唯一席位；不修改游戏revision |
| Welcome | 服务→本人：房间ID、本人席位、连接代次、能力、本人Snapshot | 初始化客户端；不返回其他凭证 |
| Intent | 客户端→服务：CommandId、MatchId、ExpectedRevision、Kind及对应参数 | 严格解析后，经房间队列调用Execute(绑定席位, command) |
| Result | 服务→发起人：CommandId、Accepted、Duplicate、Code、Message、最新本人Snapshot | 明确区分重复成功、过期和非法规则；不返回完整存档 |
| Snapshot | 服务→每个已连接席位：MatchId、Revision、本人投影 | 所有人同一提交revision，分别投影；客户端只采用更新版本 |
| Resume | 新连接→服务：现有房间凭证、上次见到的Revision | 成功后替换旧连接代次，发送当前完整本人投影，不补发原始命令日志 |

参数仅映射现有Command.Value、TargetSeat、Destination、MoveMode及Kind。每个Kind列独立允许字段，不允许额外字段或布尔值冒充整数。CommandId保持当前不超过100字符的约束；网络帧和字符串另设有限上限，超过后在执行前拒绝。具体上限由真实最大候选/投影测量确定，不能为了省带宽截断合法手牌或待选择。

房间队列按一次提交依次完成执行、需要的持久化和投影发布。两名玩家同时提交相同ExpectedRevision时，最多一条新命令成功；另一条得到stale_revision和本人新投影。客户端据新投影重新确认意图，不悄悄换revision重发原目标。相同CommandId及相同完整内容可原样重试，接受历史中至多出现一次；复用ID但修改任何参数仍为command_id_conflict。

客户端将CommandId和待确认意图保存至收到Result。断线后可在续连成功时重试原消息，不能自动生成新ID。重复结果里的投影可能比原接受revision更新，客户端不得回退到旧画面。Snapshot没有新revision时只更新连接状态，不重演卡牌动画或金币奖励。

首个切片先采用完整本人Snapshot，保留已证明的隐私逻辑。事件增量、压缩和历史分页在测量实际负载后另做；尤其不能将公共事件序号直接等同于某席可见事件数量。对局记录增长造成的恢复和投影成本分别测量。

## UI接入

Unity展示层增加会话访问接口，热座适配继续调用当前GameSession，网络适配只持有最近本人GameView和发送入口。所有合法目标仍由服务端规则产生；网络客户端不会建立能读取其他手牌的影子GameSession。

联网时1—4只允许查看公开角色信息，不能更换认证操作者；手牌固定为本人。待其他人选择时显示操作者和原因，隐藏其候选。断线时保留最后画面但禁止提交，续连后清除过期本地预选，恢复服务给出的Pending与合法选项。放弃、弃牌和防御均须等Result，不能先在客户端执行奖励或牌区变动。

## 持久化的单独门槛

当前SaveCurrent保存热座全信息；网络连接不能访问它。NET-01报告必须明写是否只有进程内断线恢复。若实现服务重启恢复，则需追加日志提交边界、崩溃截断检测和凭证恢复设计：不能先向客户端宣布成功，再因落盘失败静默丢弃已确认操作；也不能在持久化失败后继续广播新状态。此部分通过后才承诺进程重启可恢复。

## 验收与备选

最低验收为四个实际客户端完成选英雄、出生、四人确认、揭示和完整四回合，再至少经过一次对方防御/弃牌Pending断线续连。逐项案例和分批步骤见[NET-01验收设计](../../planning/NET-01验收设计.md)。只通过直接调用GameSession的四席测试不算网络验收。

直接广播完整GameState虽然省适配代码，却暴露暗选、手牌和私有来源，不能使用。首批就采用点对点同步或Host迁移，会把身份、同步和权威切换同时引入，定位失败较难，因此先保留单一权威。完整Snapshot增加带宽，但首批规则与恢复路径清楚，适合建立可核对基线。

回退方式是关闭尚未默认启用的网络入口，继续使用现有热座；不改变既有内容与引擎版本，不迁移或覆写用户存档。实施结束后以实际进程报告、协议样例、隐私检查和构建证据把本ADR从proposed转为accepted。
