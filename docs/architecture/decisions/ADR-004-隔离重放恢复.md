# ADR-004：在隔离会话中恢复命令历史

状态：已实现；专项9项及完整Unity394项通过，原生长存档恢复从84.23秒降至5.67秒。

## 问题和证据

第18轮沙盒存档含700条接受命令、838,936字节。优化前Windows Player从启动到完整恢复及第一份QA快照耗时84.23秒，CPU82.19秒，超过本次设定的15秒读取预算。输入与实际程序集见artifacts/performance/before-replay-fc9c202176f446368d3e0961bd081c7f。墙钟包含启动、规则重放、首次布局及QA截图，不当作纯算法基准。

LocalGameFactory.Restore调用每条实时Execute。实时入口需要拒绝时保留原对局，并返回按身份投影的合法操作；恢复中的中间对局尚未暴露给调用者，这些视图没有消费者。逐步复制不断增长的历史和执行地图查询，是可移除的额外工作。

## 决策

Application提供静态GameSession.Replay工厂。它复制正式内容和新的初始状态，建立尚未返回给外部的独立会话；初始进度、回执及接受命令必须为空。所有历史命令继续使用Execute的身份、对局ID、命令ID、内容指纹、重复/冲突、revision和规则应用检查，并按相同方式记回执和接受命令。

该局部会话的中间步骤不生成视图，不为拒绝回滚复制整份累积历史。一旦任一步拒绝或被认定为重复，整个工厂抛出invalid_replay，局部会话不返回；调用者提供的初始状态和内容也不受修改。只有全部命令成功才返回会话。

LocalGameFactory仍先严格解析存档，核验版本、正式内容及命令数量，再从规范的初始状态恢复。最后逐字比较规范化后的完整保存结果；金币、候选、事件、回执、规则版本变化等任何伪造仍会被拒绝。不会直接信任存档内的最终状态作为恢复结果。

普通Execute继续持有锁、复制草稿、在成功后替换权威状态，并返回按身份隔离的视图。恢复出的会话后续也使用这条实时路径；不存在可由外部命令打开的“跳过校验”开关。核心仍不引用Unity。

## 兼容与验收

这是内部执行成本变化，不增加卡牌能力，不改变命令格式、指纹、引擎版本或保存结构。旧版本存档继续按原版本能力重放，规则升级仍位于历史中明确记录的位置。

专项检查覆盖隔离输入、重复/冲突、过期revision、越界身份、错误对局、非法规则、非初始起点、私有强制弃牌待选以及恢复后继续执行与重复提交。完整核心394项、历史夹具、29份原生逐步场景442步均已通过。相同700条历史在优化后程序中测得5.67秒、CPU2.36秒，完整输入哈希保持95634758744984abb5d1293d433e017809264053ae748c06e07b040dc425dd74，报告见artifacts/performance/after-replay-7977f5a55f874d2b99a81dc93ac01ddb。

另外将优化前四组长局的原始场景交给新版Player，468、700、453、700步共2321条命令全部通过，四份最终完整存档哈希分别与优化前一致。报告见artifacts/simulations/5617f24c65e647518aec2a9eab3f2dcb/player-replays/fe6b0cae5bdc4d0fb5d96162c48429d3。原程序、失败的超预算测量和首次九项未实现测试均保留，不改写历史证据。单次端到端测量是这台机器和指定存档的结果，不承诺所有机器固定耗时。

此方案不解决实时视图随历史增长的成本。后续若实际操作仍有明显延迟，应单独测量视图投影和界面布局，再决定增量公开历史或精确复制当前投影，避免在本次恢复优化中混改。
