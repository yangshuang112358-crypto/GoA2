# 架构说明

状态：BATCH-02已实现纯C#四层核心、Rules内卡程序注册、战斗/反制/持续效果及轮末升级循环，Unity UI Toolkit负责展示和输入。Editor固定6000.3.23f1，依据见[ADR-002](decisions/ADR-002-工具链与基础切片.md)。Networking与完整触发/替换系统仍是目标设计；当前实装证据见[工作记录](../verification/BATCH-02工作记录.md)。

## 边界

- Domain：纯状态、ID、坐标、命令、事件、结果、PendingChoice。
- Rules：阶段、合法行动、路径、战斗、兵线、升级、效果原语；纯 C#，不依赖 UnityEngine。
- Cards：数据解析、Schema、合同/效果定义与少量受约束的特例处理器；通过注册入口进入规则，不往主回合塞 cardId 分支。
- Application：身份授权、用例、公共私有投影、revision、幂等、保存与回放接口。
- Presentation：Unity 场景、UI、动画、音效；展示权威结果，不自行求合法性。
- Infrastructure：持久化、时钟、随机、内容导入和日志适配。
- Networking：只传 Intent、Result、Event、Snapshot；接入时间在基础对局形成后，接口与隐私从开始建立。

实际依赖方向为Presentation → Application/Infrastructure → Rules → Domain；Rules/Cards是Rules程序集内的描述符与文本绑定注册表，不是另一个运行时。它限定按卡ID绑定的入口，共享阶段/战斗/选择代码不按卡ID分支。领域不引用UI、网络SDK或磁盘全局状态。Networking未来作为Application的另一调用方接入。

~~~mermaid
flowchart LR
    UI[Unity界面] --> App[GameSession]
    IO[内容与存档适配] --> App
    Net[未来网络入口] -.-> App
    App --> Rules[阶段与合法查询]
    Rules --> Cards[卡程序与条件描述符]
    Rules --> Domain[纯C#状态与事件]
    Cards --> Domain
~~~

## 状态与命令

GameState记录规则/内容/协议版本、revision、阶段与轮回合、四席和队伍、地图单位、战区水晶标记、卡区状态、先攻待处理队列、金币等级被动、活跃效果、所有待选择、随机状态与胜者。
PlayerIdentity 和热座观察/控制视角分开；进入用例时校验实际操作者，再交给规则校验选择者。
命令记录 command_id、match_id、actor、expected_revision、payload；客户端不得指定“伤害已算完”或直接更改单位位置。
失败命令不改任何状态、不增加revision、不写成功事件；重试相同 command_id 不重复发金币或弃牌。

## 效果与恢复

目标模型区分Instant / Triggered / Continuous / Replacement。现有CardExecution保存卡ID、控制者、程序/版本、游标、目标、攻击明细、嵌套防御反制，以及攻击前弃牌和锁定距离。ActiveEffect保存来源、拥有者、区域类别与持续窗口；PendingChoice保存选择者、来源可见性、候选和恢复点。尚未把目标模型中的所有触发和替换类型做成通用系统。
不用不可序列化闭包保存继续执行位置，不依赖Unity场景隐藏变量。
事件窗口的具体规则由牌合同决定；架构支持before/replace/resolve/after/cleanup，并不自动规定所有竞争优先级。
确定性采用注入随机源或保存结果，不直接调用UI/系统时间随机。

现有GameSession在身份、命令ID/指纹和revision校验后克隆状态执行，成功才提交；失败不留下部分修改。恢复从InitialEngineVersion重放完整接受命令，支持显式向前UpgradeEngine，再比较派生状态。固定旧档按原字节登记哈希，新字段只采用明确默认值，细节见[规则引擎版本](decisions/ADR-003-规则引擎版本.md)。公开与每席投影分别生成，热座切换显示不赋予新的授权身份。

## UI与网络早期验证

首个可运行里程碑就显示真实地图、四席、卡牌与一个可操作命令。以后每条规则同步给出可操作入口。
从开局就测试每席私有视图；联网验证先覆盖四客户端完成一轮和选择恢复，不等108张牌全部做完才发现身份问题。
真实联机以总计4名玩家为准，Host是否同时是一名玩家需在联网ADR写清，避免“Host+4玩家”无意变成5席。
