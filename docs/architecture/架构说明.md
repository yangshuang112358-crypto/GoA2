# 架构说明

状态：BATCH-01已实现纯C#四层核心与Unity UI Toolkit基础切片，Editor固定6000.3.23f1，依据见[ADR-002](decisions/ADR-002-工具链与基础切片.md)。Cards效果层、Networking、战斗与轮末仍是后续设计，下文包含完整目标模型，不表示所有字段和行为已经落地。当前实装证据见[本批验收](../verification/BATCH-01进展.md)。

## 边界

- Domain：纯状态、ID、坐标、命令、事件、结果、PendingChoice。
- Rules：阶段、合法行动、路径、战斗、兵线、升级、效果原语；纯 C#，不依赖 UnityEngine。
- Cards：数据解析、Schema、合同/效果定义与少量受约束的特例处理器；通过注册入口进入规则，不往主回合塞 cardId 分支。
- Application：身份授权、用例、公共私有投影、revision、幂等、保存与回放接口。
- Presentation：Unity 场景、UI、动画、音效；展示权威结果，不自行求合法性。
- Infrastructure：持久化、时钟、随机、内容导入和日志适配。
- Networking：只传 Intent、Result、Event、Snapshot；接入时间在基础对局形成后，接口与隐私从开始建立。

依赖方向：Presentation/Networking/Infrastructure → Application → Rules → Domain；Cards → Domain，通过接口注入 Rules/Application。领域不引用 UI、网络 SDK 或磁盘全局状态。

## 状态与命令

GameState记录规则/内容/协议版本、revision、阶段与轮回合、四席和队伍、地图单位、战区水晶标记、卡区状态、先攻待处理队列、金币等级被动、活跃效果、所有待选择、随机状态与胜者。
PlayerIdentity 和热座观察/控制视角分开；进入用例时校验实际操作者，再交给规则校验选择者。
命令记录 command_id、match_id、actor、expected_revision、payload；客户端不得指定“伤害已算完”或直接更改单位位置。
失败命令不改任何状态、不增加revision、不写成功事件；重试相同 command_id 不重复发金币或弃牌。

## 效果与恢复

Instant / Triggered / Continuous / Replacement 分开。保存 source_card、source_unit、controller、step_index、bindings、duration、created_sequence、pending_choice。
不用不可序列化闭包保存继续执行位置，不依赖Unity场景隐藏变量。
事件窗口的具体规则由牌合同决定；架构支持before/replace/resolve/after/cleanup，并不自动规定所有竞争优先级。
确定性采用注入随机源或保存结果，不直接调用UI/系统时间随机。

## UI与网络早期验证

首个可运行里程碑就显示真实地图、四席、卡牌与一个可操作命令。以后每条规则同步给出可操作入口。
从开局就测试每席私有视图；联网验证先覆盖四客户端完成一轮和选择恢复，不等108张牌全部做完才发现身份问题。
真实联机以总计4名玩家为准，Host是否同时是一名玩家需在联网ADR写清，避免“Host+4玩家”无意变成5席。
