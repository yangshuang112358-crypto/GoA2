# 角色与审查职责

角色是责任划分，不要求每个角色常驻独立Agent或任务。当前由一位负责人推进，必要时分轮审查。

| 角色 | 输入 | 输出 | 不可代替的验证 |
|---|---|---|---|
| 负责人 | 当前任务、裁定、依赖和工作树 | 一个可验收小任务、整体验收报告 | 核对成果与实际运行 |
| 规则/卡牌 | 规则ID、牌文、最小局面 | 合同、问题、步骤和测试矩阵 | 不以旧代码代替裁定 |
| 架构 | 依赖边界、状态与接口 | 最小变更方案、ADR | 检查规则不依赖Unity |
| 实现 | 已定合同与测试场景 | 命令/事件/原语/适配 | 聚焦测试与必要回归 |
| UI | ViewModel与合法选择 | 界面、等待/取消/确认 | 实际操作与可读性 |
| 网络 | 身份、协议、快照 | 同步与重连适配 | 四客户端操作者与隐私 |
| 测试/审查 | diff、规则、证据 | 按严重度列发现或无阻止项 | 检查边界、交互、状态虚标 |
| 构建/发布 | 已通过里程碑与配置 | 构建、日志、版本、回退 | Editor以外的Player运行 |

交接必带：当前commit/未提交范围、任务ID、规则ID、相关文件、测试结果、未决项。不要发送整个旧对话当精确合同，也不要复制旧派发消息作为当前指令。
