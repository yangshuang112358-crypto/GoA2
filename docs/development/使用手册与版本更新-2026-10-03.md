## 3. 第一次让三位朋友加入

先让一位好友连通，再增加到四人。

1. 四个人下载同一游戏包，右键“全部解压”，打开解压后的文件夹，再双击 `Start-Multiplayer.cmd`。
2. 房主点击“创建房间并进入”，等“房间已准备好”，游戏会自动打开。
3. 房主回到启动器，依次选择席位2、3、4，各导出一个邀请文件，分别私发给三位好友。
4. 好友在自己的启动器点击“导入邀请并加入”，选自己收到的 JSON 文件。等待自动组网、认证，然后游戏自动打开。
5. Windows 首次询问本包 easytier-core.exe 是否允许联网时，点击“允许”。程序不会要求关闭整个防火墙。
6. 四人完成选英雄、部署、暗选，各自确认后揭示。无需启动 EasyTier GUI，不用填写 IP、网络名称、密码或 TOML。

同一邀请只能对应一个席位；不要三个人共用同一个文件。免费节点可用性和中国跨网延迟仍需实际验证。

## 4. 每次开局、退出与重连

每次开局：开启动器 → 房主创建新房 → 分别发三个新邀请 → 好友导入。

房主需保持电脑和启动器运行。只关闭游戏时，可点“重新打开游戏”回原席位。好友退出连接后可“重新加入上次房间”，前提是房主仍保留原房。游戏内断线可在设置中重连；不确定操作沿用原ID查询/重试，不重复创建身份。

结束时先关闭游戏，再点击“取消／停止本次连接”。房主看到“房间已停止并验证存档”后再关启动器。当前保存用于排错和恢复资料，尚无从旧存档重开网络房间继续玩的用户入口。房主停止后所有好友都会断线。

旧手动／局域网入口仍需自行完成 EasyTier 或局域网连接，旧 TOML 和旧邀请只在那里使用。

## 6. 每次版本更新，你需要做什么

1. 先结束当前对局并正常停止房间。现阶段不要在进行中的房间混用新旧客户端，也不承诺更新后继续旧局。
2. 让开发者给出“已验证的新联机ZIP”，包含客户端、房主服务、启动器和清单。只拿到一个新exe或一次Git提交不算更新完成。
3. 四个人完整解压到一个新目录，不覆盖正在运行的旧目录；第一次验证前保留上一个可用ZIP。
4. 四个人确认包名/版本一致；房主的启动器也必须来自新包。旧桌面快捷方式若仍指向旧目录，需要更新。
5. 自动模式无需维护 EasyTier 配置；不要把旧邀请或 TOML 当作新房邀请。
6. 从新包创建新房并发新邀请。先检查进入、选英雄、暗选与确认、攻击/防御/弃牌、轮末/升级、断线重连；再完成一次真人整局。
7. 确认新包可用后清理重复ZIP和旧解压目录，保留当前包、上一可用包及永久engine34基线。

版本交付分为三件事：源码提交并推送；验证对应源码的构建；制作并分发联机包。代码已上云不会自动更新朋友电脑。未来自动更新也必须在退出对局后实施，并校验签名/哈希与失败回退。

可以直接把下面这段发给开发助手：

> 请读取AGENTS.md和《使用手册与版本更新-2026-10-03.md》，核对experiment/ai-level-20260920实际Git状态。为当前已完成改动做对应验证，必要时重建Unity Player和房主服务，生成同源四人联机ZIP，校验文件清单和SHA256，确认不含邀请、密钥、日志或存档。把最新版、手册和快捷方式整理到桌面Goa2V1，保留上一可用包及engine34永久基线。提交并推送日常分支，上传经验证的发行包，给我更新内容、包名、下载链接、每人需要做的步骤和仍未验证项。不要移动main或永久回退引用，不把本机模拟测试称为四人异地真人验收。

## 7. 遇到问题怎么反馈

连不上：先看启动器停在哪个阶段，检查房主仍开房、每人邀请不同、包版本相同。等待连接结果后可取消重试。节点故障与席位认证是不同问题；自动模式不以 Windows 是否出现虚拟 IP 判断成功。

窗口卡住：记录时间、包名、操作步骤、是否刚启动/切出切回/正在响应，先保留窗口以便取证。2026-09-30曾记录AppHang及NVIDIA超时，之后两分辨率重连正常，尚未定位根因；不要把它直接判成网络故障或已修复。

反馈模板：

> 包名：___；发生时间：___；我是房主/席位___；刚才做了___；预期___；实际___；是否能重复___。请先检查日志和进程，不清空存档、不泄露邀请；如需重启房间先说明会断开所有人。

日志：`%LOCALAPPDATA%/Goa2V1/Multiplayer/player-*.log` 与对应 `auto-*/` 中的 worker/network 日志及房间 server-error.log。房间的private子目录含邀请和权威存档，不能整包发到公开群或公开issue。单机存档在 `%USERPROFILE%/AppData/LocalLow/Goa2V1/Goa2V1/saves`。

## 8. 开发、测试和美术入口

以下在Goa2V1项目根目录执行，普通测试人员不需要运行这些命令。Python用已安装的真实解释器，本机为 `C:/Users/29383/miniconda3/python.exe`。

```powershell
# 资料结构、引用和生成视图一致性
python -B tools/validate.py
python -B -m unittest discover -s tests -v
# 规则测试；Unity图形测试与构建串行执行
./tools/test-core.ps1
./tools/test-unity.ps1 -Graphics -Assemblies 'Goa2.UI3D.Tests' -Filter 'Goa2.UI3D.Tests.MinionModelTests;Goa2.UI3D.Tests.Board3DTests' -ReportName minion-check
# 编译客户端，再打包自带运行时的四人联机版
./tools/build-unity.ps1
python tools/player_package.py verify-build artifacts/player --source-root .
./tools/package-multiplayer.ps1 -PythonExe 'C:/Users/29383/miniconda3/python.exe' -Label four-player
# 本地试玩、列出手工局面、从完整行动起点开始
./tools/run-player.ps1
./tools/open-debug-position.ps1 -List
./tools/open-debug-position.ps1 -Name axe-ready
```

运行包不用安装Unity或.NET SDK；美术编辑用Blender。源文件 `art/minions/Goa2_Minion_Collection.blend`，操作见 `art/minions/README.md`。骨架语义可通用，各英雄可以有不同模型及独立动画。再次运行模型生成器会覆盖脚本输出，手工精修前保存副本。

恢复源码用正常Git历史或独立工作树；永久标签 `baseline/2026-09-20-engine34`、分支 `baseline/engine34-20260920`不移动。禁止直接用旧版本覆盖当前未提交工作。
