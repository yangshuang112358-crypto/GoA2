# Goa2V1可执行程序与命令总表

> 本文保留夜间逐卡开发前的盘点基线和通用指令。最新版本、完整牌单与测试数字见[当前功能与测试说明](当前功能与测试说明.md)及[夜间逐卡记录](../verification/夜间卡牌工作记录-2026-09-13.md)；player同级的运行命令文本随每张牌更新。下文旧版计数不代表当前版本。

核对日期：2026-09-13，引擎12。以下按仓库实际脚本参数整理；列出入口不代表这些脚本本次全部重跑。结果与边界见[项目现状](项目现状与联机路线-2026-09-13.md)。全部命令在Goa2V1仓库根目录执行，推荐PowerShell 7；程序测试窗口不要与其他真实输入测试并行。

## 1. 环境和普通玩家入口

| 用途 | 需要什么 | 启动方式 |
|---|---|---|
| 玩本地热座/游戏内调试 | 完整Windows player目录 | 双击artifacts/player/Goa2V1.exe，或`./tools/run-player.ps1` |
| 离线查资料 | 浏览器 | 打开artifacts/reference/Goa2V1-资料浏览器.html |
| 开发/编辑Unity | Unity 6000.3.23f1及已激活许可 | Hub添加unity目录，打开Assets/Scenes/Main.unity；Goa2/Prepare project后Play |
| .NET核心测试 | global.json指定SDK 10.0.401及锁定依赖 | `./tools/test-core.ps1`；无需Unity窗口 |
| Python资料工具 | Python 3.12+ | 使用下方`$GoaPython`或实际解释器；无需第三方Python库 |
| 浏览器自动测试 | Node.js、Playwright、Microsoft Edge | 使用下方`$GoaNode`及test-data-browser.cjs |
| 联网服务/客户端 | 尚不存在 | 没有可用的服务器exe、房间命令或端口，NET-01仍待实现 |

玩家运行完整Windows包不需要安装Unity Editor或.NET SDK。开发脚本支持-UnityExe/-DotnetExe/-PythonExe等参数；Unity批量构建/测试前关闭正在打开同一工程的Editor，重建Player前关闭该程序。

本机现有Python、Node入口可在PowerShell中设置一次；其他电脑替换成各自路径：

```powershell
$GoaPython = Join-Path $env:USERPROFILE '.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
$GoaNode = Join-Path $env:USERPROFILE '.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe'
```

本机.NET在`%LOCALAPPDATA%\Goa2V1Toolchain\dotnet\dotnet.exe`，脚本可自动找到；Unity在`%USERPROFILE%\UnityEditors\6000.3.23f1\Editor\Unity.exe`。它们是本机工具位置，不是源码必须固定的路径。Python的Windows商店别名不能代替已安装解释器。2026-09-12已实际运行.NET测试宿主与原生Player，早期“本机被应用控制阻挡”的记录是历史状态。

## 2. 游戏、保存和手工局面

```powershell
./tools/run-player.ps1
./tools/run-player.ps1 -Qa -Width 1600 -Height 1000
# 先关闭已跟踪窗口，再从指定保存恢复到独立QA工作副本
./tools/run-player.ps1 -Qa -LoadSave '实际存档.json'

./tools/open-debug-position.ps1 -List
./tools/open-debug-position.ps1 -Name riposte
# 只生成并验证起点，不开窗口
./tools/open-debug-position.ps1 -Name occupied-spawn -PrepareOnly
# 明确替换本工具跟踪的窗口；不用于普通游戏存档
./tools/open-debug-position.ps1 -Name upgrades -ReplaceTrackedPlayer
```

run-player支持宽1152—3840、高768—2160，默认1600×1000。启动脚本通常只允许一份已跟踪可见Player；这不提供多个网络身份。

| 预设Name | 起点 |
|---|---|
| axe-ready | 飞斧开始攻击前 |
| axe-cost | 飞斧本人决定支付弃牌或跳过 |
| axe-reflection | 飞斧已支付成本，被反射后另一次强制弃牌 |
| spear-existing | 已有弃牌的长矛支付窗口 |
| riposte | 有手牌攻击者选择弃牌或被击败 |
| riposte-empty | 空手攻击者已攻击，虎爪待选防御 |
| riposte-victory | 攻击者队伍只剩1水晶，选择被击败会结束对局 |
| upgrades | 两名角色各自升级 |
| respawn | 选择出生点并继续原牌 |
| occupied-spawn | 队长处理被占出生格 |

游戏内用“调试→打开测试局面…”也能进入；支持搜索。金币、配牌、传送、弃回牌、基础测试攻击、快进等通过游戏内调试面板完成，写入命令记录。正常“新对局”目前建立测试局；关闭快选只切换确认流程，不会将Sandbox权限变成正式联机权限。

普通存档在`%USERPROFILE%\AppData\LocalLow\Goa2V1\Goa2V1\saves\hotseat-v1.json`；QA在artifacts/unity/qa-save.json。读取来源用-LoadSave；需要指定写入位置时，原生exe可传`-goaSavePath "绝对路径"`，读取可传`-goaLoad "绝对路径"`。仅启动exe不会自动把所有历史包中的存档合并。

## 3. 数据、构建和共享测试

```powershell
# 正式数据、文档链接、来源与旧档哈希
& $GoaPython -B tools/validate.py
# Python工具测试
& $GoaPython -B -m unittest discover -s tests -v
# 上述两项的PowerShell封装
./tools/validate.ps1 -PythonExe $GoaPython

# 内容修改后更新生成的目录/准备稿；正式源仍是content/canonical
& $GoaPython -B tools/generate_views.py
# 同步经校验的正式内容及调试场景到Unity
& $GoaPython -B tools/prepare_unity.py

# 共享C#测试；Auto当前优先.NET
./tools/test-core.ps1
./tools/test-core.ps1 -Runner Dotnet
./tools/test-core.ps1 -Runner Unity
# Unity局部用例；无需先手工打开Editor
./tools/test-unity.ps1 -Filter Goa2.Tests.RiposteChoiceTests -ReportName riposte-choice
# 默认仅核心程序集；呈现测试可指定Goa2.Presentation.Tests
./tools/test-unity.ps1 -Assemblies Goa2.Presentation.Tests -ReportName presentation

./tools/build-unity.ps1 -Task Prepare
./tools/build-unity.ps1 -Task Validate
./tools/build-unity.ps1 -Task BuildWindows
```

Prepare同步内容并准备工程；Validate核验Editor集成；BuildWindows输出artifacts/player。核心结果artifacts/tests/core.trx，Unity测试artifacts/unity/tests，构建artifacts/unity/build-report.json及日志。Auto仅在明确的Windows应用控制宿主错误时回退Unity，断言失败不会被当作环境错误跳过。

core下四个.NET项目为类库，不是四个可单独启动的游戏；tests/Goa2.Core.Tests为测试宿主。正式程序不带这些测试程序集。

## 4. 场景运行和可视化

```powershell
# 已构建程序，全部38份正式场景
./tools/run-scenarios.ps1
# 先重建再执行
./tools/run-scenarios.ps1 -Build
# 指定一份；去掉-Visual即可同源无窗口运行
./tools/run-scenarios.ps1 -Scenario tests/scenarios/riposte-decline.json -Visual -Paused -KeepOpen -Delay 0.75
# 场景播放工具自身的真实输入验收
./tools/test-playback-ui.ps1
```

可见播放一次选择一份；-Paused/-KeepOpen需要-Visual，-Delay为0—10秒，-TimeoutSeconds默认300。窗口内可单步、继续/暂停，播放结束“转为手工操作”。无窗口版本使用同一Player/ScenarioRunner并跳过界面，报告在artifacts/scenarios/场景/模式/运行编号。tests/fixtures/scenario-failure.json故意失败，不在默认38份集合中。

## 5. 真实游戏界面测试：15模块

```powershell
# 默认全部15模块、1280×800；窗口会被实际鼠标键盘操控
```

## 6. 布局、阅读、长局与性能专项

```powershell
./tools/test-readability-ui.ps1 -Width 1600 -Height 1000
./tools/test-card-reading-ui.ps1 -Width 1280 -Height 800
# 无-Visual的Player模式检查布局；截图验收用可见模式
./tools/test-card-layout.ps1 -Visual -Width 1280 -Height 800
./tools/test-card-layout.ps1 -Editor -Width 1600 -Height 1000
./tools/test-revealed-stripes.ps1 -Visual

# 生成固定种子长局；当前生成入口使用Unity EditMode
./tools/test-simulations.ps1 -Games 8 -Steps 400 -Seed 101
# 再在原生Player重放全部，第二局可见播放
./tools/test-simulations.ps1 -Games 8 -Steps 400 -Seed 101 -ReplayPlayer -Visual -VisualIndex 2 -Delay 0.1
# 已生成批次：替换成其真实32位编号
./tools/replay-simulations.ps1 -BatchId '已有32位编号' -Mode Both -VisualIndex 2 -Delay 0.02

# 需要一份沙盒、Planning阶段的长存档；原始文件不改写
./tools/test-long-ui.ps1 -SavePath '实际长存档.json' -InteractionBudgetMs 1500
# 启动至出现恢复后画面，默认15秒预算
./tools/measure-player-load.ps1 -SavePath '实际存档.json' -Label e10 -BudgetSeconds 15
```

test-card-layout/test-revealed-stripes支持-Visual、-Editor、-UnityExe；它们包含实际布局查询与合成指针，不能称为物理鼠标输入。readability/card-reading检查具体阅读交互。隐藏Player可能输出黑色截图，几何通过不等于图片通过。

模拟Games为1—64、Steps为40—900；达到step_limit与实际match_finished分开统计。导出期望部分来自生成器，证明确定性与跨环境一致性，不能替代逐卡手写预期；模拟器不是玩家AI。长档工具支持-Width/-Height；measure另有-PlayerDirectory用于明确选择旧版作对照及-TimeoutSeconds，见各脚本param。

证据分别在artifacts/card-layout、revealed-stripes、simulations、long-ui、performance。没有复跑的长局历史不能当新引擎的完整长局通过。

## 7. 单步QA工具

先以run-player.ps1 -Qa启动，使本次窗口写出新布局并记录PID。以下命令实际控制前台游戏：

```powershell
./tools/qa-player.ps1 -Action Capture -Name manual
./tools/qa-player.ps1 -Action Key -Key 1
./tools/qa-player.ps1 -Action Key -Key Space
./tools/qa-player.ps1 -Action Click -Caption '^调试$' -AutoScroll
# 仅在相应按钮存在的局面使用
./tools/qa-player.ps1 -Action Hover -Caption '^确认不弃牌并被击败$' -AutoScroll
./tools/qa-player.ps1 -Action Scroll -X 1450 -Y 700 -WheelDelta -480
./tools/qa-player.ps1 -Action Drag -X 700 -Y 500 -ToX 800 -ToY 550
# 先实际聚焦搜索输入框，再输入文字
./tools/qa-text.ps1 -Text '近身还击'
```

Caption为文字匹配，Element为稳定控件名；X/Y必须取自当前布局而非照抄示例坐标。Key支持1/2/3/4/Home/Escape/Tab/Enter/Space/F1。工具仅读取布局并发送真实输入，不直接执行规则命令；输出截图及.ui.json在artifacts/unity。ui-qa-common.ps1是供测试引用的函数库，没有独立主程序。tools/data-browser.html是生成器模板，也不是带完整资料的成品。

## 8. 离线浏览器、打包和源码验收

```powershell
& $GoaPython -B tools/build-data-browser.py
Invoke-Item './artifacts/reference/Goa2V1-资料浏览器.html'
# Edge浏览器自动检查；加--visual观看
& $GoaNode tools/test-data-browser.cjs
& $GoaNode tools/test-data-browser.cjs --visual

& $GoaPython -B tools/player_package.py verify-build artifacts/player --source-root .
./tools/package-player.ps1 -PythonExe $GoaPython -Label e10-local
# 将生成包的实际路径赋值；不要把占位文字当真实文件名
$GoaArchive = 'artifacts/releases/实际生成的包.zip'
& $GoaPython -B tools/player_package.py verify-archive $GoaArchive
# 从独立解压目录运行其中的Player
./tools/test-release-player.ps1 -Archive $GoaArchive -Scenario tests/scenarios/riposte-decline.json

./tools/test-release-content-ui.ps1 -Archive $GoaArchive

./tools/test-source-checkout.ps1 -Commit HEAD -PythonExe $GoaPython
./tools/test-source-checkout.ps1 -Commit HEAD -PythonExe $GoaPython -UnityTests
```

player_package.py还提供底层创建命令：`& $GoaPython -B tools/player_package.py create artifacts/player artifacts/releases/自定新包.zip --source-root .`，拒绝覆盖已有包。verify-build比对源输入；若不一致，应重新构建，不应修改清单绕过。程序包必须保留整个Goa2V1子目录。

build-data-browser.py可传--root/--output；validate.py可传--root/--report；prepare_unity.py可传--root；generate_views.py使用脚本所在仓库。报告输出分别在artifacts/reference、reference-tests、releases、release-smoke、release-content-ui、source-checkouts。GitHub Actions当前仅负责内容/Python/.NET/Unity数据准备，原生构建和真实输入仍在本机验收。
