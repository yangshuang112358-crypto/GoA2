# 场景脚本合同 v1

目的：同一份输入既能在Player无窗口运行，也能在可见Player中按步骤展示。两种路径必须调用同一ScenarioRunner和GameSession；图形路径只增加展示、暂停和单步，不重新计算规则。与真实鼠标/键盘验收分开报告。

输入JSON包括SchemaVersion=1、Id、Name、Seed、Sandbox、四名Players、VerifyReplayAfterEachStep及Steps。Id为1—64位小写字母/数字/连字符。最多1000步、输入最多2 MiB；重复键、未知字段、无效命令、空场景拒绝。JSON不能指定外部文件读写路径。

每步包括Name、Actor、Command、Value、Target、Destination、MoveMode、AuthenticateAs和Expect。Actor/Target使用p1—p4，另有active/chooser/blueCaptain/redCaptain；需要测试越界身份时可写p0或p5。AuthenticateAs默认与Actor相同，用于验证身份伪造拒绝。Destination为{X,Y}轴坐标，MoveMode为Secondary或Fast。

ReplayStep为从1开始的已有步骤序号；提供时重复原命令全部字段，包括ID和原修订，不能再指定新Command，以验证幂等、旧修订与失败后的行为。

Expect.Code默认ok；其他拒绝码或duplicate必须明确写出。期望包括Phase、Round、Turn、Active、PendingKind、PendingChooser、Revealed总数、各席位Gold/HandCounts/DiscardCounts、指定单位Positions、本步产生的EventCounts与顺序子序列EventOrder。Active=none明确要求没有行动席位。错误码正确但期望状态不符仍是失败。

每步都保存实际命令、接受/重复标志、错误码、状态摘要和SHA256。所有被拒绝的命令必须满足完整状态零修改；默认每步保存后从命令日志恢复并继续，以验证中断选择也可恢复。复现时不使用随机GUID或系统时间作为命令/对局ID。

任何步骤失败立即停止后续步骤，保存失败点及最后有效状态；无窗口进程返回非零。可见模式明确显示失败，不自动开始另一场游戏。图形/无图形运行必须得到相同最终状态哈希。

该文件是测试工具的工程合同，不为卡牌或对局添加规则。当前实现状态见BATCH-02工作记录。

战场期望可选字段：CombatRegion、Winner（Blue/Red/none）、BlueMarks/RedMarks、BlueMinions/RedMinions、BlueCrystal/RedCrystal。小兵计数排除英雄；胜者与标记分别检查，不能通过单一Phase推测胜负。范例见tests/scenarios/frontline.json。

轮末期望：RoundEndStage为none/minion_battle/upgrades，RemainingMinionRemovals为当前数量差剩余，UpgradingPlayers为仍待选择人数。各席位Levels限定1—8、UpgradeCounts限定0—6，PurpleCards写正式紫卡ID或none。这些字段检查实际派生状态，不能只因命令被接受就通过。范例见tests/scenarios/round-upgrades.json和round-frontline.json。

持续效果期望：EffectCounts按来源卡牌ID检查当前保存的效果数量，包含已调度但尚未生效的记录；到期删除后为0。PrimaryRestrictions按p1—p4检查各自当前已揭示牌的主要行动禁止来源，none表示没有该禁止原因。它不表示整张牌已实装，也不等于当前轮到该角色。范例见tests/scenarios/static-field.json与skill-suppression.json；正式核心测试另检查效果起止、动态区域和合法路径。

攻击期望：AttackBase、AttackBonus、CardTextBonus、AttackFinal分别检查当前保留的攻击明细；AttackBonus是永久与牌文加成总和，CardTextBonus是其中牌文项。没有当前攻击时不能把空值当0通过；Final允许负值。通常放在ChooseAttackTarget之后的防御窗口；攻击已结束清除执行器后，这些期望应省略。示例marksman.json与headshot.json。
