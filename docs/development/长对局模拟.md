# 可重放的长对局模拟

这是测试驱动器，不是产品AI。使用正式资料、GameSession和每个身份的合法查询选择命令；不直接改权威状态，不推测未实装牌文。普通模式完成四人分别选择并确认，沙盒模式四人选完即揭示。沙盒仅在起步阶段通过已有调试命令增加金币、装配已支持牌、调整水晶及聚集英雄，随后走普通行动和选择。

随机数采用固定32位xorshift和稳定排序，同一种子、参数及代码产生相同输入与命令ID。英雄从六名正式英雄中选四名；动作偏向已有主要行动和靠近敌人的合法移动，但保留放弃、普通防御和不防御的路径。升级从合法候选选择。缺失的选择处理或没有合法延续会明确失败并保留现场，不通过重新抽种子掩盖。

每条接受命令检查单位ID/位置唯一、单位在地图上、五色牌数量、英雄与复活状态、等级/金币、命令/回执/修订数、事件顺序和公开投影。每25步及第一次出现各类待选择窗口后，从完整命令记录恢复；每17步检查冒名拒绝，每25步在恢复后重复上一命令，要求完整存档不变。最终再次恢复。生成的场景再由ScenarioRunner执行并比较完整存档。

默认核心回归只有两局、各120步，以及确定性和占位检查两个测试。扩大运行：

~~~powershell
./tools/test-simulations.ps1 -Games 8 -Steps 400 -Seed 101
# 所有生成场景在原生Player无窗口重放，再把第2局可见播放
./tools/test-simulations.ps1 -Games 8 -Steps 400 -Seed 101 -ReplayPlayer -Visual -VisualIndex 2 -Delay 0.1
~~~

Games为1—64，Steps为40—900，模式按正式/沙盒交替。Player须已构建；改变核心后先重建，否则比较会揭示版本差异。测试只存在Editor测试程序集，不进入发行Player。脚本仅临时设置GOA_SIM_*环境变量，结束后恢复原值。

SeededGame显式允许单项运行最多一小时。Unity框架默认三分钟会将已完成但超时的长局判为失败，因此不使用短单元测试的默认时限；其他测试保持原时限。退出码和XML仍须通过，生成报告不能代替NUnit结果。

已经生成的输入可独立在Player重放，无须重新随机生成或覆盖旧报告：

~~~powershell
./tools/replay-simulations.ps1 -BatchId 已有32位运行编号 -Mode Both -VisualIndex 2 -Delay 0.02
~~~

独立重放要求各局生成和场景重放报告均成功，并比较原生程序最终状态哈希；结果写到该批player-replays的新编号目录。即使原NUnit因测试时限失败，这份单独证据也不会改写原失败XML或batch.json。更换引擎后应使用当时的程序或重新生成新批次，不能把不同版本输入的哈希差异当作随机波动。

artifacts/simulations/运行编号内保存batch.json；每局包含独立命名的场景输入、report.json和final-save.json，失败另外保留before-failure.json及最后尝试命令。报告区分达到步数上限step_limit和实际胜利match_finished，前者不是“完成一局”。统计实际命令、事件、恢复检查点和遇到的未实现主牌。

导出场景默认VerifyReplayAfterEachStep=false：生成时已经按检查点恢复，场景层再重放全部命令并比较最终存档。需要逐步恢复时，可复制生成场景并将此字段设为true，然后使用run-scenarios.ps1运行；长输入的每步完整历史重放会增加耗时。导出断言来自生成结果，验证的是确定性和跨运行环境一致性，不能替代逐卡手工指定期望的规则测试。真正的鼠标/键盘交互仍由test-player-ui及各牌UI脚本验收。
