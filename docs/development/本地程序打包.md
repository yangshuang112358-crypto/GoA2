# 本地Windows程序打包

当前可运行包及其精确哈希、独立解压结果见[BATCH-02验收](../verification/BATCH-02验收.md)。

Unity构建成功后，artifacts/player/build-info.json记录实际Unity版本、引擎/规则/协议版本、正式内容哈希及当时核心公开的已支持主要行动/防御卡。逐文件登记构建输入与Player内容的字节数和SHA-256；输入在构建中途变化会使此次构建验收失败。

程序内容损坏的可见检查使用tools/test-release-content-ui.ps1 -Archive 程序包.zip。它先验证包，在独立解压副本暂存一份卡数据，检查资料缺失错误页、无错误读档动作和无存档写入；恢复原文件后重新校验全部内容并打开四席，7项结果单独保存于artifacts/release-content-ui。原压缩包和开发程序不改动。

输入范围包括核心Runtime、Unity Assets/Packages/ProjectSettings、正式content，以及用于游戏内调试预设的tests/scenarios和tools/debug-positions.json；自动生成的StreamingAssets/Goa2与Goa2Debug副本由原始输入和Player文件记录覆盖。测试程序集及测试报告不属于程序包。资料状态和测试结论仍由独立报告证明，构建清单不会把“有该程序集”当作“全部牌测试通过”。

~~~powershell
./tools/build-unity.ps1 -Task BuildWindows
./tools/package-player.ps1 -Label e8-local
# 验证、解压到独立目录，再启动包内程序执行场景
./tools/test-release-player.ps1 -Archive 'artifacts/releases/实际程序包.zip'
# 可见播放同一份验收；结束自动退出
./tools/test-release-player.ps1 -Archive 'artifacts/releases/实际程序包.zip' -Visual
~~~

打包先核对当前输入文件集合及字节，再核对每个Player文件。源代码变化、程序文件变化、额外文件、缺少核心程序集或没有构建清单时均拒绝。输出新的artifacts/releases/Goa2V1-标签-时间-编号.zip，不覆盖已有压缩包；同目录保存外层SHA-256和打包报告。压缩包内部只有Goa2V1程序文件夹与构建清单，不包含源目录或本机绝对路径。

解压后运行Goa2V1/Goa2V1.exe即可，无需安装Unity Editor。独立复核压缩包内容：

~~~powershell
python -B tools/player_package.py verify-archive 路径/Goa2V1-标签.zip
~~~

Python工具使用标准库；package-player.ps1优先寻找本机已有的捆绑Python，也可传-PythonExe。校验读取压缩包内的清单并逐文件比对，无需解压或读取原项目。它验证内部完整性，不代替实际启动、场景回归或发布平台验收；当前仅生成本地测试交付物。

test-release-player.ps1先核验压缩包路径与所有字节，解压至artifacts/release-smoke的新编号目录，再核验解压后的清单。输入场景复制到该目录，工作目录为解压目录；Player通过包内StreamingAssets读取正式资料。报告、日志及存档写在程序文件夹外，保持包内容可继续校验。默认执行投掷飞斧/反射屏障场景，可用-Scenario指定其他场景；报告保留包哈希、清单哈希、输入哈希、退出码及末态哈希。

## 从独立源码重建

~~~powershell
./tools/test-source-checkout.ps1 -Commit HEAD -UnityTests
~~~

该工具通过git archive导出指定已提交版本，解压到artifacts/source-checkouts的新编号目录。从不含Library及生成资料的副本运行资料校验、可选完整Unity测试、Windows构建和20步原生场景。工作目录也切换到副本，不使用原项目Player。报告登记源提交、归档哈希、初始无缓存/生成数据状态及各门槛结果；不会删除原目录或覆盖旧归档。

这验证源项目可以在独立路径、没有原项目Library时重建，仍使用本机已安装且有许可的Unity，以及可用的全局包缓存/工具链；不把它称作一台从未安装过环境的新机器验收。未提交修改不进入导出的源码。
