# AI原子观察与关系模型重构

日期：2026-10-08。分支：`feature/ai-training`。本批用户允许推翻旧输入，不要求兼容。

**已重写数据投影和模型输入，观察4 / 行动2 / 编码器3。旧1805＋242维模型停止用于新格式，旧实验原件保留。信息完整性仍标记为false：完整牌文机制描述和部分公开事件细节尚待结构化。**

## 对九个问题的逐项结论

| 问题 | 结论与本批处理 |
|---|---|
| 1. 队伍资源/状态为何求和 | 旧模型为缩小向量做了粗汇总，但损失所有权。例如甲3金币＋乙7金币和甲7＋乙3不可区分，升级机会可能完全不同。删除等级、金币、手牌、复活、中毒、石化的队伍汇总；逐角色保留。水晶生命、推进标记本来属于队伍，仍分别记录蓝队和红队。 |
| 2. 四类单位是什么 | 英雄、近战小兵、远程小兵、重型小兵。类型可以是类别特征，不能用“每类数量＋平均位置”代替单位。现逐个记录单位，关联控制者、阵营、精确格子；离场引用和待出生单位分别表达。 |
| 3. 地图常量与最近距离 | 出生点、基地、兵线、障碍和区域必须能被模型访问。它们是每个内容版本提供一次的静态上下文，动态观察不重复传。模型计算时仍读取地图实体。删除最近敌人距离；未来可作为明确标注的派生特征做消融实验，不能替代精确位置。几何距离不等于合法路径、移动成本或实际威胁。 |
| 4. 本人牌区为何那么大 | 原来把全部108种卡×5个牌区展开为540个位置，大部分为0；并非本人有540张牌。现在每名角色只保存实际装备的卡，每张记录所有者、稳定卡ID、牌区和出牌时间。本人记录可含自己的暗选，别人未揭示的Selected仍由核心投影为InHand。 |
| 5. 是否还有漏项 | 有，见下方明确缺口。已补紫卡、逐人状态/加成、效果区域/豁免/持续期、完整公开行动链、路径、防御和升级查询事实、时间化公开历史。不能因此宣称已覆盖全部规则语义。 |
| 6. 当前公开焦点牌 | 它是公开行动链的FocusId指向的牌，不是鼠标悬停牌，也不是别人正在暗选的牌。旧编码为108维独热，只能表示一张牌。现在删除CurrentCard单独入口，在行动链节点记录Focused、Started、Resolved、角色、先攻和父响应关系。 |
| 7. 总手牌、出牌回合、等待复活 | 总手牌数可从每名角色的牌区推导，删除重复手牌数；每人单独保留AwaitingRespawn。每张牌保存PlayedRound/PlayedTurn，公开历史也有轮次、回合和事件顺序，因此可区分同牌多次打出/取回/结算。当前牌区快照不能替代历史。 |
| 8. 哪些重复值得删 | 删除本人牌区的第二份副本、队伍牌区统计、按卡牌全集展开的牌区向量、单位均值、最近距离、手牌和复活人数总和。卡牌色别等静态属性只放目录；候选用引用关联卡/单位/目的格，不再把ID的UTF-8字节当连续数值。 |
| 9. 进一步改进 | 改为可变长度实体＋明确关系；空值与0分开；所有字段有归属，未知字段/类别及容量超限显式失败。加入字段覆盖登记、暗选不变性、实体顺序不变性、同总和不同分配可区分等验证。先补语义完整性，再扩大训练。 |

不能把“所有可推导量都删掉”当作一条绝对原则。当前保留的有效加成、技能作用区域、可移除标志、防御成功和攻防算式，是**C#正式规则查询结果**。它们可能由原始状态推导，却包含条件、例外和牌效，作为公开提示可降低学习负担。基础事实与这些查询结果分别记录，不在Python复制规则，也不把二者当独立真值。

例如Permanent.Attack是长期获得的攻击加成，Effective.Attack是中毒等影响后的当前有效值；BasicAttackBonus只影响基础攻击。它们有不同语义，不能因为某局数值相同就合并。Attack.Bonus包含TextBonus/UltimateBonus，不能再把这两项重复相加；Final保留正式引擎结果。

## 输入边界与数据组织

`GameSession.View(实际决策席位)` → AI白名单投影 → 观察4与合法候选2 → 关系图编码器3 → 策略网络 → 稳定候选ID → 正式`Execute`。

| 记录 | 原子字段/关系 | 为什么保留 |
|---|---|---|
| 对局 | 当前轮/回合、阶段、响应类型、战斗区域、公开决策币；本人/行动者/队长引用；蓝红生命与标记；轮末步骤、剩余移除次数、当前攻击距离 | 决策者和当前行动者可能不同；团队胜利状态保留双方实际值。 |
| 规则 | 初始水晶生命、胜利标记、每轮回合、手牌规模 | 支持按明确规则配置重新评测，不把7生命/3标记写死在神经网络中。泉水胜利规则没有改变。 |
| 角色 | 稳定英雄ID、阵营、等级、金币、确认/复活/中毒/中毒含防御/石化状态、永久和有效六项加成、基础攻击专属加成、紫卡引用 | 每名角色独立，不跨队或队内相加。座位号只用于连接关系。 |
| 卡实例 | 所有者引用、卡定义引用、Zone、PlayedRound、PlayedTurn | 同一静态定义与当前实例的状态分开。没有装备某牌与装备但不在手里不同。 |
| 卡定义 | 稳定ID、所属英雄、颜色、级别、先攻、主要类别/数值、是否感叹号、范围/远程类型及数值、次要移动/防御、被动类型 | 按内容目录提供一次，数值不存在时保留null，不冒充0。显示名不作为身份。 |
| 单位 | 类型、阵营、控制者引用、格子引用、C#可移除查询标志 | 全部英雄与小兵精确定位；待出生关系与当前在场关系区分。已离场但仍被效果/历史引用的单位有无位置节点。 |
| 格子 | 轴向X/Y、障碍、兵线、基地、出生标记、区域；几何邻接关系 | 地形与生成机制是决策上下文。邻接边仅表示几何相邻，不授予移动权限。 |
| 持续效果 | 种类、来源牌/单位、保护对象、控制者/豁免者、创建轮回合、顺序、起止轮回合、持续类型、区域类型、基础半径、击败后是否保留、C#区域格子集合 | 可区分同种效果由谁施加、何时到期、覆盖谁。私人来源牌继续由本人投影遮蔽。 |
| 当前响应 | 已遮蔽来源、作用单位、是否可选 | 不传Pending内部ID、ResumeAt、私有路由。真正响应者是观察Seat。 |
| 公开行动链 | 所属轮/回合，每个公开出牌节点的所有者、牌、角色、顺序、先攻、开始/结束/焦点状态、父响应引用 | 保留主要行动、弃牌、防御、紫卡和反击之间的公开关系。节点编号只用于连边，不作为特征数值。 |
| 公开历史 | 连续公开序号、轮次/回合、事件种类、角色/牌/单位引用、移动起终点和路径；经审查解析的转移、伤害、兵战数值与结果 | 不暴露私有事件间隙，不复制带内部ID的原始Detail。历史不会按最近N条静默裁切。 |
| 本人升级历史 | 轮次、英雄/卡级、替换前/选中/未选卡、获得加成和数量 | 自己已经知道的升级选择，有助于区分同牌区但不同长期属性。 |
| 候选行动 | 种类、真正相关的模式/分支、卡/目标/目的格引用；正式路径、防御算式、升级替换、金币转移、兵返回属性、主要行动预览 | 每个合法候选单独评分。非防御行动的“防御是否成功”等不适用字段在编码时是缺失，不是假装失败。 |

区分三种情况：值为0、值未知/不适用、实体不存在。数字带presence位；不存在的引用没有该边；离场但身份仍被引用的单位保留节点且无位置。编码不用0,0假装英雄位置，也不以中文显示名或UI按钮顺序固定语义。

`ai/observation-coverage.json`登记GameView、PlayerView、GameEvent、PendingChoice、CardDefinition的所有字段。C#反射测试要求每个字段被分类；核心以后加字段却未评审，测试会失败。编码器同样拒绝未消费的新字段，防止静默遗漏。

## 新网络的实际结构

不是把旧输入换成更大的MLP。本批实现的是小型关系图网络，加候选注意力读取：

1. 每种记录有固定的数字槽位与presence位；类别值进入16维Embedding。卡牌ID是有版本字典的离散符号，不是整数大小或ID字节的连续数值。实体与候选编号只作图指针。
2. 每个节点通过共享输入层映射到64维：Linear → SiLU → LayerNorm。
3. 两层有类型的消息传递沿“所有者、所在格、来源、保护对象、父响应、路径、目标”等边交换信息，带反向边。重复的支援来源边保留次数。聚合使用求和后除以度数平方根，不在输入前求队伍均值。
4. 每个合法候选以自己的节点表示为查询，做4头注意力，读取整张公开关系图；小MLP给出一个logit，softmax只覆盖合法候选。
5. 独立价值读取查询经注意力汇聚，再由价值头给出标量V。Actor和Critic共享图编码器，输出头分开。监督选动作不伪造价值标签。

没有RNN、搜索、GAN或对手隐藏状态。公开历史有显式时间/顺序；这不等同于已验证长程记忆能力。两层图传播也不意味着自动解决所有长距离战术关系；全图注意力只是提供访问渠道。

这里“不汇总”指不在输入前把角色合并成不可恢复的队伍数值；网络内部仍会做消息聚合与注意力汇聚。区别在于先保留实体、所有权和位置，再让可训练模块读取。64维神经表示不是原始观察的无损压缩，也不能仅由架构保证模型关注了正确关系。

图的动机是保留实体与关系的归纳偏置，可参见[Graph Networks论文](https://arxiv.org/abs/1806.01261)。对不依赖数组排列的集合进行注意力读取，可参见[Set Transformer论文](https://proceedings.mlr.press/v97/lee19d.html)。本项目是自建的小型实现，不是直接复刻论文，也没有架构胜率对照证明它优于MLP、Transformer或搜索。

输入大小随实体和历史数量变化，不再说成固定1805维。基础地图254格、卡目录108种，每个实际角色/卡实例/单位/效果/事件另有节点。容量边界为16384节点、262144条有向边、候选数×节点数不超过2000000；超限报错并保留现场，绝不删合法候选或悄悄截断历史。

## 已知缺口：尚不进行“大量训练已经完整输入”的承诺

- **完整牌文机制尚未成为结构化输入。** 新模型能看到稳定牌ID、牌面数值和已生效的效果，但还没有统一的“前置条件→目标选择→执行→重复上限→到期”机制描述。它可以从训练学习已有卡ID的行为，不能因此理解新增卡牌、新例外或修改后的牌文。后续应从C#规则程序导出受审查的公共描述，不让Python解释中文重写规则。
- **部分公开事件原因/历史算式尚未完整解析。** 原始Detail中混有内部帧/效果ID，所以没有整段送入模型；已经结构化出牌、移动、目标、金币、伤害、兵战和部分结果，仍缺一些条件失败原因、生命周期原因以及历史AttackValues。当前攻击与防御算式已进入模型。
- **当前候选和预览覆盖当前可执行选项，尚不是对全部未来行动的后果预测器。** 可执行名单不等于模型理解牌效的所有条件。
- **引擎适配器仍显式限制四席。** 关系图支持变长实体集合，不等于规则核心已经支持更多玩家或任意地图。增加单位种类/机制必须更新字典、接口和测试，不能默认为旧模型认识新机制。
- **无已验证的长期历史压缩方案。** 目前保留全部已投影公开历史；如果达到资源边界，应扩充或设计带验证的记忆/压缩方案，再改版本。

固定卡池下，不一定需要直接输入自然语言牌文：稳定ID可在训练中学习对应行为。结构化机制描述的目的，是减少完全依靠试错记住每张牌，并为新内容提供有意义的属性；它也不保证自动泛化。动态状态和公开历史的遗漏则不能靠同一个卡ID补回来。

## 后续数据构造与评测顺序

先补上述语义缺口及稀有响应；按真实决策类型构造反例，例如相同队伍总数但资源换人、相同单位数但站位不同、相同牌区但出牌时机不同、同效果但到期/豁免不同。暗选身份变化应不可区分，公开事实变化应可区分。

然后重新从C#产生新版本教学与正式轨迹。训练/验证按完整对局或原始场景来源划分，不能把同局相邻帧分入两侧。均衡罕见决策仅用于训练抽样；正式评测按真实分布统计，并单独报告决策类别，避免总准确率掩盖小兵返回等退步。

在相同信息集合、种子、换边阵容和计算预算下比较关系模型与完整信息MLP/实体注意力基线；分别消融历史、静态机制描述、派生几何提示和搜索预算。当前不能把旧输入MLP与新信息图模型的差异全部归因于网络结构。

增加生命值/推进次数时，要同时保留当前值与规则目标，独立划分训练范围及未见规则评测。源提交、规则/内容哈希、观察/动作/编码版本、符号字典签名、随机种子、对手池和评测必须随模型保存。不兼容旧检查点明确拒绝；旧教学数据应重放权威记录后重新投影，不能仅把版本号改成4。
