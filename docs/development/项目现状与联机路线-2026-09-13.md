## 2. 当前程序如何运行

在Goa2V1仓库根目录的PowerShell中执行：

```powershell
# 普通本地测试程序
./tools/run-player.ps1

# 独立QA存档，适合手工调试
./tools/run-player.ps1 -Qa -Width 1600 -Height 1000

# 列出10个可继续操作的测试局面
./tools/open-debug-position.ps1 -List
./tools/open-debug-position.ps1 -Name riposte

# 无窗口执行全部32份场景
./tools/run-scenarios.ps1

# 可见、暂停起步，支持单步；结束后可转手工
./tools/run-scenarios.ps1 -Scenario tests/scenarios/riposte-decline.json -Visual -Paused -KeepOpen
```

也可直接双击artifacts/player/Goa2V1.exe。必须保留完整player目录，不要求玩家安装Unity Editor或.NET SDK。四人目前共享同一台电脑和同一个窗口：1/2/3/4切席，空格确认，地图滚轮缩放，中/右键拖动，Home全图；这不是四个网络玩家。

当前新包：artifacts/releases/Goa2V1-e10-status-20260913-20260912-161112-18b555a6.zip。包名后半段为UTC时间；北京时间为9月13日。内含引擎10、156份程序负载文件，负载107,865,719字节（约102.9 MiB，不是压缩包大小）。SHA-256为46ca6c42d836627c96ae271d83bbb6cc9a4883e21176e282779cf2faff62a46c。已验证源输入和每个程序文件哈希，并从独立解压目录通过16步近身还击场景。

artifacts/releases内e8/e9包、artifacts/delivery中的BATCH02交付、player-history及release-smoke中的程序副本均为历史或测试产物。UnityCrashHandler64.exe是Unity随附辅助程序，不是另一个游戏入口。父目录goa2_v2/v3/v4与v5为旧项目；本次不将其旧服务器列为Goa2V1的启动依赖。

## 6. 距离四人及更多人联网还差什么

已有可复用基础：确定性规则核心、连接身份参数与ActorSeat分离、按席位投影、命令ID/修订号/重复保护、可恢复待选择。**尚无网络服务可执行程序，没有房间入口、端口或四客户端运行指令。** [ADR-005](../architecture/decisions/ADR-005-四身份联网切片.md)仍为proposed，不能将设计图当实现。

| 里程碑 | 必须新增 | 可称完成的验收 | 增量工程估算 |
|---|---|---|---|
| A：四客户端内部联机 | 权威房间服务、连接绑定席位、严格消息、私有投影、串行提交、客户端会话适配、错误/重复/断线界面 | 同机四个真实客户端，各自手牌，正式确认，完整四回合；防御/弃牌待选择断线后继续，NET-01全部16项通过 | 40—80小时 |
| B：四位朋友异地受限试玩 | 选择并落实可达服务、私密房间加入/重连凭证、版本一致检查、服务部署、加密连接、诊断日志、延迟/断网处理、服务重启恢复及分发验证 | 四台实际电脑从不同网络加入，进行长局；重复请求不重复奖励，不泄露手牌，掉线/服务重启后恢复 | A后另40—80小时 |
| C：六人3v3 | 人数/队伍/队长/席位权限参数化、开局/选牌/升级/复活适配、UI与测试扩展、对应地图/出生和经济规则核验 | 六独立客户端完整长局与重连；原四人场景仍通过 | A后另40—80小时，可与B部分交错 |
| D：完整六英雄牌池 | 剩余87张、相关通用元动作、逐卡合同与调试、紫卡、代表性组合矩阵、规则歧义解决 | 108张逐卡通过，所有关键待选择可恢复，真实多人完整对局无占位功能 | 约350—750小时 |
| E：朋友可长期使用的发布版 | 长局性能、配置/存档管理、安装/更新/日志收集、教程、目标设备验证、发布回归与缺陷修复 | 指定设备和网络矩阵通过，连续多场与故障恢复可重复验证 | B/D后另40—100小时，正式美术和额外平台另算 |

以上是基于当前代码缺口的工程判断，不是测速结果或完成承诺；按一名熟悉项目的开发者、现有Windows技术栈、每日8小时有效工作估算，包含编码与验收。规则答复、外部部署条件、机器测试和重大缺陷会扩大日历时间；不同里程碑共享工作，不能简单全加。完成A后应以实测吞吐重新估算B—E。

**四人异地受限试玩粗估合计80—160小时（10—20个工作日）**，使用已支持的牌效范围，不等于完整桌游。无需等87张全部实现才验证网络；若要求六英雄全牌文都能玩，内容工作是更大的关键路径。数量比例19.4%不能反推精确剩余时间。

六人不会只是把房间上限4改为6：当前GameRules的玩家数量/ActorSeat、GameSession的私有投影、ScenarioRunner、奖励身份检查、调试自动开局及Unity快捷键均有四席假设。不能全局替换数字4，因为“四回合”和地图常量仍应保留。八人或更多还涉及当前仅六名且不可重复英雄的内容限制；具体牌池、队伍、地图、出生与经济配置须先确定。观战连接也不能算作额外可操作玩家。当前NET-01明确只接纳四席。

## 8. 优化优先级

1. **先把联网身份和会话适配做实。** 复用纯核心，客户端只持有本人投影；用四个实际进程及错误身份/重试/断线验证，避免末期才发现展示层依赖全信息状态。
2. **按代表牌补齐通用能力，再逐卡扩展。** 动作内移动与主要移动优先；持续效果、替换、触发和标记都保存来源与恢复点。坚持卡程序注册，不把card ID特判散入主回合、攻击或未来网络层。
3. **把测试局面变为逐卡工具。** 为21张已接入牌补足可搜索预设；新卡至少一个正常局面和一个交互局面。加入当前版本15模块全量、断点恢复与固定种子回归，测一次后保留版本证据。
4. **减少界面阅读与误操作成本。** 针对1280/1600实测右栏确认按钮、横向手牌滚动和完整牌文；联网明确“等待谁/为什么/能做什么”。选牌草稿不因同步刷新丢失，禁止把私有来源写入公共日志。
5. **先测长档，再优化。** 分别记录命令执行、投影生成、完整恢复、保存和画面响应；考虑受校验的检查点、记录分页与增量刷新，保留旧档完整重放基准，不用删除历史来获得速度。
6. **统一交付与状态口径。** 最新程序、内容哈希、引擎版本、源码提交、测试结果与已知限制一起登记。保留旧包和回滚依据，清理文档旧结论；正式包关闭调试权限并提供明确的新局配置。
