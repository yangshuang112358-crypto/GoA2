# 防御后处理与强制弃牌

首批使用偏转屏障和反射屏障，按已有R-DEFENSE、D-011与U-006边界实现。不能把防御后文字直接塞进选择防御牌的那一步，从而抢在攻击后的文字之前执行。

防御被接受时保存一个挂在当前CardExecution上的后处理记录：来源牌、控制者、原攻击者、程序标识/版本和游标。原攻击程序仍按游标执行；到结束入口先处理防御后步骤。需要弃牌时保留父执行器和待选择，不结束原攻击牌，不再发一次AttackResolved。最后一张牌的反制也须完成后才能进入回合边界。

强制弃牌命令只接受对应本人当前InHand牌。空手分支自动推进，界面不提供跳过；取消界面预选仅清除本地草稿，不能清除权威选择。选择、弃置和后续免疫全都可序列化和重放。调试资源接口沿用现有范围，改变牌区/单位位置等结构性调试在反制期间继续关闭。

完整存档持有防御来源和私有候选。公开视图仅弃牌者得到候选；未公开的防御/弃牌来源按SourcePrivateTo隐藏卡名，仍可显示保护事实和来源角色。先用完整快照计算所有合法集合，再进行视图脱敏，禁止脱敏影响规则查询。界面不通过猜测卡面重新计算合法手牌或免疫范围。

反射屏障使用绑定自身的免疫效果，类别是“非相邻英雄的远程攻击”，而非全局无敌或技能免疫。攻击查询与命令重检调用同一影响判断；普通主要/次要/快速移动的路径规则不因此改变。

新能力从引擎4开始；新增DTO字段不得改变原命令指纹。旧状态新增字段以空值默认，旧版本卡程序保持原选择/事件行为；固定旧档必须继续重放一致。
