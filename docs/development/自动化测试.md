# 自动化测试入口

新增战场验收：`./tools/test-battlefield-ui.ps1` 使用通过重放校验的场景准备占位出生局面，然后通过真实鼠标/键盘切换队长、全图复位、选出生格、确认、移除重型和验证泉水胜利。9项检查与截图输出到artifacts/unity；启动前关闭已有的测试Player。

战斗验收：`./tools/test-combat-ui.ps1` 从核验后的7步局面开始，以真实输入执行开始攻击、点敌方英雄、切防御者、用金牌数值防御失败、奖励与弃牌检查、选择出生点并继续原牌。10项检查、attack/defeat/respawn截图和独立存档输出到artifacts/unity。

升级验收：`./tools/test-upgrade-ui.ps1` 验证轮末费用、两张候选、非本人不可见、三色阶梯、跨角色选择、存读档、补偿及下一轮出牌槽/顶部历史。轮末移兵验收：`./tools/test-round-minion-ui.ps1` 验证先移非重型、重型推进出生打断、恢复升级和新兵不承担旧兵数量差。均支持-Width/-Height并使用真实输入。

`tests/scenarios/frontline.json`另提供7步无窗口/可见场景。场景报告验证战区、小兵数量、累计推进、胜者、金币及事件顺序，不仅检查命令是否被接受。

## 同一份核心测试，两种运行环境

核心测试唯一源码在core/com.goa2.core/Tests/Editor。tests/Goa2.Core.Tests项目引用这些文件，Unity通过包内测试程序集引用同样的文件；不复制维护两套断言。

~~~powershell
./tools/test-core.ps1
./tools/test-core.ps1 -Runner Dotnet
./tools/test-core.ps1 -Runner Unity
./tools/test-unity.ps1 -Filter Goa2.Tests.DebugFlowTests -ReportName debug-flow
~~~

默认Auto先运行.NET。只有新的TRX中所有失败均为Windows应用程序控制错误0x800711C7时，才改用Unity EditMode运行同源测试。断言失败不触发切换，也不会被忽略。可直接指定Unity，以免本机反复尝试被系统拒绝的测试宿主。

Unity6000.3.23f1自带Test Framework 1.6.0；已按[包测试的官方约定](https://docs.unity3d.com/6000.3/Documentation/Manual/cus-tests.html)设置testables和仅Editor测试程序集。框架由编辑器固定版本提供，见[官方版本说明](https://docs.unity3d.com/6000.3/Documentation/Manual/com.unity.test-framework.html)。测试程序集不进入发行Player。

Unity每次输出新的XML结果文件；脚本同时检查进程退出码、非零测试数量和Passed结果，不能把旧报告或空测试当成功。核心结果在artifacts/tests/core.trx，Unity结果在artifacts/unity/tests。不同运行环境报告分别保存，不合并成虚假的全部环境通过。

## 实际界面输入

关闭现有Player，运行tools/test-player-ui.ps1；可指定-Width 1280 -Height 800。它打开真实窗口、发送鼠标和键盘，检查19项交互，使用独立QA存档。工具只向已跟踪且在前台的Goa2V1发送输入。

tools/qa-player.ps1可用于单步Capture/Click/Scroll/Drag/Key；-Caption按文字匹配，-Element按稳定控件名匹配，-AutoScroll通过真实滚轮将右栏按钮滚入可见区。它不调用内部按钮回调，也不直接改游戏状态。

## 资料校验

python -B tools/validate.py与python -B -m unittest discover -s tests -v覆盖正式资料、哈希和导入工具；这层结果不能作为游戏规则或卡牌行为的通过证据。

## 同源场景，可选可视化

~~~powershell
# 先构建，再无窗口运行全部正式场景
./tools/run-scenarios.ps1 -Build
# 可见播放一份场景，完成后保留窗口供检查
./tools/run-scenarios.ps1 -Scenario tests/scenarios/sandbox-smoke.json -Visual -KeepOpen
# 暂停起步，可按窗口中的“执行下一步”，或“继续场景”
./tools/run-scenarios.ps1 -Scenario tests/scenarios/formal-turn.json -Visual -KeepOpen -Paused -Delay 1
~~~

运行已构建版本时省略-Build；重新构建前先关闭旧Player。可见场景一次选择一份，默认每步0.75秒，-Delay可设置0—10秒。未传-KeepOpen时播放结束后自动退出。运行场景期间可查看角色和缩放地图；报告写完后，“转为手工操作”解除场景对对局的控制。

两种模式都运行同一个Player和ScenarioRunner。无窗口模式使用-batchmode -nographics跳过界面，保持相同命令、恢复和断言流程。每次运行有独立输出目录artifacts/scenarios/文件名/模式/运行编号，包含逐步报告、最终完整存档、日志、输入哈希及五个项目程序集哈希；各模式latest.json指向最近结果内容。

目前十九份场景共285步：sandbox-smoke（9步）、permissions（7步）、formal-turn（23步）、frontline（7步）、spawn-order（7步）、combat-defense（17步）、round-upgrades（25步）、round-frontline（17步）、static-field（13步）、skill-suppression（12步）、shining-blade（15步）、deflection-barrier（19步）、reflection-barrier（22步）、marksman（13步）、headshot（14步）、cleave/deadly-sweep/death-spin（各17步）、backstab（14步）。默认每步从保存的命令重放后继续；状态不符、意外错误或拒绝命令产生部分修改时立即失败。场景层验证规则命令及恢复，与真实鼠标/键盘验收分别报告。

持续效果真实窗口验收：`./tools/test-auras-ui.ps1`，支持-Width/-Height，先验证并载入三份场景的起步存档，再用真实键鼠检查22项：技能按钮、来源、范围显示、范围内移动/越界高亮过滤、禁止提示、放弃、到期、顶部公开记录、闪耀之刃防御后取消与相邻封技、定位角色。脚本只关闭本工具跟踪且路径正确的QA Player，不使用正常用户存档。

tests/fixtures/scenario-failure.json故意含错误断言，用于验证失败路径；单独运行它应返回失败，只执行第一步，不能继续增加金币。它不包含在默认通过场景集合中。

屏障真实窗口验收：`./tools/test-barriers-ui.ps1`，支持-Width/-Height。两份场景核验后，真实点击攻击、防御、强制弃牌及取消预选；中途关闭并从待弃牌状态恢复，检查不重复攻击/弃牌。第二名攻击者实际查看免疫目标被排除并攻击另一合法英雄，直到免疫到期。16项检查与pending/resumed/protected截图保存在artifacts/unity。

神枪手/一枪爆头真实窗口验收：`./tools/test-marksman-ui.ps1`，支持-Width/-Height；10项检查实际牌文+2、目标未行动/已放弃基础攻击、相邻目标与非相邻屏障条件、数值防御成功/失败。各卡牌UI脚本共用ui-qa-common.ps1的启动、存档、选格和真实输入助手；助手本身不执行游戏命令。

相邻攻击真实窗口验收：`./tools/test-adjacent-attacks-ui.ps1`，支持-Width/-Height。四张牌22项检查五名相邻敌方的三档乘数、受保护重型可计数但不可攻击、来源文字、普通小兵修正独立、背刺排除本人且多人只提供一次+2、挑战者比较与下一次行动。1280×800实际窗口已通过，截图逐张保存。

写场景参考[场景脚本约定](场景脚本约定.md)。JSON字段大小写和标量类型严格验证，不把布尔值或小数隐式转换成整数，不接受缺失坐标分量。
