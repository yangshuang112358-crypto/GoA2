## 同一份核心测试，两种运行环境

核心测试唯一源码在core/com.goa2.core/Tests/Editor。tests/Goa2.Core.Tests项目引用这些文件，Unity通过包内测试程序集引用同样的文件；不复制维护两套断言。

~~~powershell
./tools/test-core.ps1
./tools/test-core.ps1 -Runner Dotnet
./tools/test-core.ps1 -Runner Unity
./tools/test-unity.ps1 -Filter Goa2.Tests.DebugFlowTests -ReportName debug-flow
~~~

默认Auto先运行.NET。只有新的TRX中所有失败均为Windows应用程序控制错误0x800711C7时，才改用Unity EditMode运行同源测试。断言失败不触发切换，也不会被忽略。可直接指定Unity，以免本机反复尝试被系统拒绝的测试宿主。

Unity6000.3.23f1自带Test Framework 1.6.0；已按[包测试的官方约定](https://docs.unity3d.com/6000.3/Documentation/Manual/cus-tests.html)设置testables和仅Editor测试程序集。框架由编辑器固定版本提供，见[官方版本说明](https://docs.unity3d.com/6000.3/Documentation/Manual/com.unity.test-framework.html)。测试程序集不进入发行Player。

Unity每次输出新的XML结果文件；脚本同时检查进程退出码、非零测试数量和Passed结果，不能把旧报告或空测试当成功。核心结果在artifacts/tests/core.trx，Unity结果在artifacts/unity/tests。不同运行环境报告分别保存，不合并成虚假的全部环境通过。

## 实际界面输入

统一入口为tools/test-ui-suite.ps1，默认在1280×800依次执行15个模块；可用-Case smoke,presets,recovery,gallery等选择，-ContinueOnFailure允许记录失败后继续其他模块。每次保存在artifacts/ui-suites/新编号，包含各模块新报告、截图、存档、日志、脚本哈希及测试前后完整程序文件哈希。拒绝旧报告、空检查和测试中程序变化；默认遇失败停止并保留现场。运行前会关闭路径核验通过的已跟踪QA Player，测试使用真实前台输入，不要同时运行另一份界面脚本。

~~~powershell
./tools/test-ui-suite.ps1
./tools/test-ui-suite.ps1 -Case smoke,optional-discard -Width 1152 -Height 768
~~~

关闭现有Player，运行tools/test-player-ui.ps1；可指定-Width 1280 -Height 800。它打开真实窗口、发送鼠标和键盘，检查19项交互，使用独立QA存档。工具只向已跟踪且在前台的Goa2V1发送输入。

tools/qa-player.ps1可用于单步Capture/Click/Scroll/Drag/Hover/Key（含F1）；-Caption按文字匹配，-Element按稳定控件名匹配，-AutoScroll通过真实滚轮将右栏按钮滚入可见区。它不调用内部按钮回调，也不直接改游戏状态。

图鉴使用tools/test-gallery-ui.ps1，检查中文/牌号输入、108张全英雄检索、21张当前可用牌、空结果、输入数字不切角色、旧引擎0仍为5张和完整存档不变，共12项。tools/qa-text.ps1通过[Windows SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)与[KEYEVENTF_UNICODE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput)发送实际字符，每字检查已跟踪Player仍在前台；不通过剪贴板或界面内部回调填值。

## 资料校验

python -B tools/validate.py与python -B -m unittest discover -s tests -v覆盖正式资料、哈希和导入工具；这层结果不能作为游戏规则或卡牌行为的通过证据。

其中历史夹具由tests/fixtures/manifest.json逐字节登记，目前八份旧档、七份输入，共15份文件。校验也核对版本、命令数量及是否漏登记；新增捕获须附原程序取证说明。九项夹具测试加十一项资料导入测试不替代Unity核心或实际Player验收。

较长的命令组合检查使用[长对局模拟](长对局模拟.md)。test-simulations.ps1可指定种子、局数和步数；-ReplayPlayer比较原生无窗口结果，-Visual选择其中一局可见播放。达到步数上限与实际获胜分开记录。

## 同源场景，可选可视化

~~~powershell
# 先构建，再无窗口运行全部正式场景
./tools/run-scenarios.ps1 -Build
# 可见播放一份场景，完成后保留窗口供检查
./tools/run-scenarios.ps1 -Scenario tests/scenarios/sandbox-smoke.json -Visual -KeepOpen
# 暂停起步，可按窗口中的“执行下一步”，或“继续场景”
./tools/run-scenarios.ps1 -Scenario tests/scenarios/formal-turn.json -Visual -KeepOpen -Paused -Delay 1
~~~

运行已构建版本时省略-Build；重新构建前先关闭旧Player。可见场景一次选择一份，默认每步0.75秒，-Delay可设置0—10秒。未传-KeepOpen时播放结束后自动退出。运行场景期间可查看角色和缩放地图；报告写完后，“转为手工操作”解除场景对对局的控制。

tools/test-playback-ui.ps1单独验证播放工具本身：先跑无窗口9步，再用真实键鼠暂停起步、单步、继续/暂停和转手工，共12项。它检查播放期间手工命令不能改动场景，末态与后台一致，转手工后能加金保存且不覆盖原场景结果。使用PowerShell 7的ThreadJob运行现有场景入口；初始界面必须为本次启动的新快照。证据在artifacts/playback-ui，与15模块游戏界面套件分别计数。

两种模式都运行同一个Player和ScenarioRunner。无窗口模式使用-batchmode -nographics跳过界面，保持相同命令、恢复和断言流程。每次运行有独立输出目录artifacts/scenarios/文件名/模式/运行编号，包含逐步报告、最终完整存档、日志、输入哈希及五个项目程序集哈希；各模式latest.json指向最近结果内容。

当前32份场景共477步，完整集合为tests/scenarios中的JSON文件，包含BATCH-03测试攻击与BATCH-04两份自主还击场景。默认每步从保存的命令重放后继续；状态不符、意外错误或拒绝命令产生部分修改时立即失败。场景层验证规则命令及恢复，与真实鼠标/键盘验收分别报告。EventCounts和EventOrder只检查当前步骤新产生的事件。

持续效果真实窗口验收：`./tools/test-auras-ui.ps1`，支持-Width/-Height，先验证并载入三份场景的起步存档，再用真实键鼠检查22项：技能按钮、来源、范围显示、范围内移动/越界高亮过滤、禁止提示、放弃、到期、顶部公开记录、闪耀之刃防御后取消与相邻封技、定位角色。脚本只关闭本工具跟踪且路径正确的QA Player，不使用正常用户存档。

tests/fixtures/scenario-failure.json故意含错误断言，用于验证失败路径；单独运行它应返回失败，只执行第一步，不能继续增加金币。它不包含在默认通过场景集合中。

屏障真实窗口验收：`./tools/test-barriers-ui.ps1`，支持-Width/-Height。两份场景核验后，真实点击攻击、防御、强制弃牌及取消预选；中途关闭并从待弃牌状态恢复，检查不重复攻击/弃牌。第二名攻击者实际查看免疫目标被排除并攻击另一合法英雄，直到免疫到期。16项检查与pending/resumed/protected截图保存在artifacts/unity。

神枪手/一枪爆头真实窗口验收：`./tools/test-marksman-ui.ps1`，支持-Width/-Height；10项检查实际牌文+2、目标未行动/已放弃基础攻击、相邻目标与非相邻屏障条件、数值防御成功/失败。各卡牌UI脚本共用ui-qa-common.ps1的启动、存档、选格和真实输入助手；助手本身不执行游戏命令。

相邻攻击真实窗口验收：`./tools/test-adjacent-attacks-ui.ps1`，支持-Width/-Height。四张牌22项检查五名相邻敌方的三档乘数、受保护重型可计数但不可攻击、来源文字、普通小兵修正独立、背刺排除本人且多人只提供一次+2、挑战者比较与下一次行动。1280×800实际窗口已通过，截图逐张保存。

条件防御真实窗口验收：`./tools/test-conditional-defenses-ui.ps1`，支持-Width/-Height及-Case指定melee-block、riposte-hand、riposte-empty、riposte-victory、lead-charge、lead-charge-unavailable或riposte-ranged；默认all。覆盖合法抵挡、本人强制弃牌、空手击败/胜利、私有来源、友兵条件、相邻远程仍不能近身还击、不可用原因及固定顶部胜者。单用例报告另加名称后缀，不覆盖完整报告。

写场景参考[场景脚本约定](场景脚本约定.md)。JSON字段大小写和标量类型严格验证，不把布尔值或小数隐式转换成整数，不接受缺失坐标分量。

投掷牌真实窗口验收：`./tools/test-optional-discard-ui.ps1`，支持-Width/-Height。22项检查攻击前可选弃牌/明确跳过、本人候选、成本保留、条件距离、存档恢复、反射屏障独立强制弃牌及无目标结束。小窗口通过实际折叠顶部面板呈现距离3的目标；公共Select-Cell先核对地图可视边界，禁止把屏幕外目标误点到其他控件。

本地程序完整性及解压启动见[本地程序打包](本地程序打包.md)。12项Python测试覆盖源文件变化、缺件、混入文件、路径、哈希、压缩包篡改、禁止覆盖及调试预设输入变化；test-release-player.ps1从新的独立目录运行压缩包内程序，可指定-Visual。

读取错误和保存故障使用tools/test-recovery-ui.ps1。它只改写独立QA存档副本，覆盖损坏JSON、伪造金币、未来引擎、错误内容、文件缺失、保存临时路径不可写、新对局保留、启动重试和重新开始；原始失败输入单独保留。保存故障由在QA临时路径创建空目录注入，结束核验路径和空目录后移除，不修改系统权限。

长档实际响应检查使用tools/test-long-ui.ps1 -SavePath 某份沙盒Planning存档。它读取完整历史，连续切换角色、核对左栏与地图、执行一次+5金币，再关闭/恢复新增命令。默认1500毫秒交互预算包含输入工具固定等待及新快照，不能当作纯规则执行时间。原存档不被修改，证据保存在artifacts/long-ui。

离线文档和地图的浏览器检查另见[离线资料浏览器](离线资料浏览器.md)。这套检查与Unity规则、原生场景和真实游戏键鼠分开计数。

[手工调试局面](手工调试局面.md)提供十个预设。open-debug-position.ps1 -PrepareOnly只运行原生验证和存档生成；省略该参数会打开可见窗口，并切换至当前选择者。每次生成独立证据目录，实际revision取自存档，正确处理场景中的拒绝和重复命令。

长存档读取测量使用tools/measure-player-load.ps1 -SavePath 实际存档.json。工具先复制输入，再启动可见程序，等待该进度的新界面快照；默认15秒预算、180秒超时，超预算或未恢复返回失败。报告含实际输入/程序集哈希、完整启动到快照的墙钟时间及进程CPU时间；这是端到端观测，不等同于纯规则计算时间。可用-PlayerDirectory指定旧程序作对比，-Label区分版本，所有证据在artifacts/performance的新编号内。
