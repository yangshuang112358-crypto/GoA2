# 自动组网与邀请加入 · 2026-10-03

本批实现原一体化方案 A 阶段。验收结果及发行包以同日 verification 文档为准；本文件描述最终接口，不把设计当作跨电脑已通过。

## 操作

完整解压新版包 → `Start-Multiplayer.cmd`。房主点“创建房间并进入”，准备好后依次导出席位 2、3、4 邀请并分别私发；好友点“导入邀请并加入”。双方都保持启动器运行。每次新开房间换邀请；同房重连可用“重新加入上次房间”。旧邀请保留在手动／局域网入口使用。

Windows 首次可能弹出该包 easytier-core.exe 的防火墙联网提示，允许后有利于 P2P；程序没有关闭防火墙或自动增删其规则。无需 EasyTier GUI、虚拟网卡或管理员安装。是否真正直连和中国跨网延迟必须实测。

## 层次和边界

`Launcher.ps1` → `AutoLauncher.ps1`（WinForms 主线程）→ 独立 `BootstrapWorker.ps1` → `Goa2.Network.exe` / EasyTier core。UI 通过原子写入状态文件和停止请求与 worker 协作；不在 UI 线程进行联网等待。运行资料限当前用户与 SYSTEM 访问。

房主规则服务仍只监听 loopback 随机 TCP 端口。房主运行三个隔离的 EasyTier 通道，每个只连接一位好友；三条通道共用同一规则房间。用户态网络中房主为 10.233.42.1，好友按席位使用 .2—4；这个网段不注册到 Windows，所以不依赖实际网卡地址，也不改变默认路由。好友本机只监听 127.0.0.1 的随机转发端口，通往房主虚拟地址的游戏端口。原游戏票据只改本机连接端点，房间 ID、席位凭据、协议、内容版本保持原样。

每位好友通道分别使用随机网络身份与 256 位密钥；统一邀请含 schema、网络 profile、节点、个人票据和席位编号。网络身份不替代游戏认证。邀请不带脚本、命令、任意代理网段或运行程序路径。文件限制 64KiB，节点限制 1—4 个严格 TCP/UDP 地址；schema、密钥、席位、票据与本包能力版本全部先验证。

房主网络只允许该游戏 TCP 端口入站，其他 TCP 与全部正常 UDP 服务被拒绝。好友不导出本机服务；双向已建立 TCP 返回由上游有状态 ACL 处理。RPC 只监听 loopback。没有 SOCKS 通用入口、家庭子网代理、DNS 修改、UPnP 自动开洞或虚拟网卡驱动。

Windows Job 只包含本次 worker 及其网络/规则子进程。正常退出先请求原有 Stop/Restore 验证保存，失败时保留仍运行的规则服务供重试；worker 异常终止时 Job 清理其子进程，不能把异常关机视为已保存。用户已有 EasyTier/VPN 不归它管理。游戏由 UI 启动，不在 worker Job 中被强杀。

## 网络依赖的实际调整

上游 v2.6.4 官方 Windows core 硬依赖 Npcap Packet.dll；其许可不等同于 EasyTier LGPL。没有将该 DLL 放入游戏包。专用构建保留 `smoltcp,socks5,aes-gcm` 编译功能（socks5 功能承载端口转发，不开放 SOCKS 服务），关闭默认抓包、TUN、DNS 等功能；Windows 网卡枚举仍用原生 network-interface，移除失败时的 pnet 抓包回退，并去掉 vendored pnet_datalink 的 Packet 静态链接声明。精确源码、Cargo.lock、构建脚本及许可同包/同 Release 提供。

构建入口 `.github/workflows/easytier-userspace.yml` 与 `tools/build_easytier_userspace.py`；实际产物哈希见 `network/easytier-userspace.lock.json`。网络组件可独立替换，修改本机 component.json 的对应哈希即可，不限制 LGPL 组件的修改或调试。无收费网络服务。

## 验证入口

- `network/tests/unified_invite.ps1 -Package <完整包目录>`：邀请格式、版本、输入注入、组网配置边界。
- `network/tests/automatic_network.py <包目录>`：本机真实独立节点与本地中继、四 TCP 席位、同步、重连、取消、ACL、异常清理、保存。
- 同命令加 `--public`：通过实际公共初始节点发现；仍是同一台电脑，不能替代异地验收。
- `network/tests/invite_launcher_os.py <包目录> <新证据目录>`：独占 OS 键鼠，开房、导出、导入、两个真实 Player、停止保存；遇受保护窗口会停止输入，不假报通过。
- 旧 `network/tests/portable_launcher.ps1` 保留原手动入口与 authority 回归。旧 OS 脚本改为打开 ManualLauncher。

不改卡牌、核心规则、Command/View、Unity 展示或存档格式。Player 沿用已验证的 9 月 30 日源码构建并重新校验，而非宣称重新构建 Unity。昵称、账号、房间列表、短房间码、迁移房主、旧房重开、本地局转网络局均未在本批实现。

依据：[EasyTier 官方组网说明](https://www.easytier.cn/guide/network/quick-networking.html)、[上游 v2.6.4](https://github.com/EasyTier/EasyTier/tree/v2.6.4)、[Npcap 许可](https://github.com/nmap/npcap/blob/master/LICENSE)。

## 本次接入排错记录

旧 public.easytier.cn / .top 的公共 DNS 查询已返回 NXDOMAIN，不能继续写入默认配置。使用社区发布的 us01.225284.xyz 当前地址 38.147.105.185:11010；不把 TCP 端口打开等同于组网成功，必须通过真实席位认证。本机原有代理/VPN保持不动。国内旧节点 8.148.29.206 本次中继传输探测超时，没有纳入默认入口。

公网复验发现延迟优先选路在此网络环境出现不稳定路由，改用默认最短路径；初始连接20秒未完成时，好友会保留房间和席位、只重启自己的通道为仅中继，再继续尝试。握手读取采用8秒单次、15秒总读取上限，避免把中继延迟误判成身份失败。最终四席公开节点回归结果以验收文档为准。

社区节点发布入口：https://github.com/orgs/EasyTier/discussions/1848 。网络名称/密钥和票据不进入文档或公开包。

四节点共享网络虽然曾通过一次，但最终候选包重复发生公共节点下的路由/认证超时；两节点16KiB强制中继传输正常。因此改为三个相互独立的房主—好友通道，共用同一个原有权威服务，不依赖好友之间的网状路由。主机正常退出和异常Job回收均覆盖全部三条通道；最终验证以新包报告为准，不用旧单次通过掩盖复测失败。此设计增加房主两个轻量网络进程，不增加玩家操作。
