# 直接打开手工调试局面

在测试对局中打开右侧“调试”→“打开测试局面…”，选择下表中的局面，再点“保存并加载”。程序先验证新局面，再保存当前对局，最后切换到可继续操作的角色。取消保留整份当前对局；选择窗口内的1—4不会切换背后的角色。此入口及全部局面随Windows程序附带，使用菜单无需命令行或Unity Editor。

当前共19份预设，列表可搜索、滚动；19份准备状态均由当前核心回归验证，原生与真实输入证据见BATCH-04工作记录。正式确认且非Sandbox的存档不提供此入口。测试对局的快速选牌与正式确认开关仍独立控制；局面切换不会把正式对局变成测试对局。

2026-09-13按用户最新要求，卡牌用例统一从完整行动开始前进入，攻击、弃牌、防御和后续移动由你亲自执行。右侧“最近记录”以及展开的完整记录会显示本用例的操作方法与简单分支；保存后重开同一局面也保留说明。升级、复活、出生三个公共规则专用用例仍直接进入对应流程。

在项目根目录运行以下命令，省去逐一配牌和摆位。需要已经构建的Windows Player；不需要打开Unity Editor。

~~~powershell
./tools/open-debug-position.ps1 -List
./tools/open-debug-position.ps1 -Name axe-cost
./tools/open-debug-position.ps1 -Name respawn -Width 1280 -Height 800
# 明确替换本工具正在跟踪的Player；正常游戏存档不被使用
./tools/open-debug-position.ps1 -Name upgrades -ReplaceTrackedPlayer
# 只验证并生成存档，不开可见窗口
./tools/open-debug-position.ps1 -Name occupied-spawn -PrepareOnly
~~~

每次从tests/scenarios的验收场景复制所需前缀，使用当时的Player验证全部步骤，再核对最终阶段和待选择类型。非法命令及重复步骤保留在前缀内，恢复使用实际revision，不能假定“第17步就是revision17”。局面来源、输入和存档哈希、引擎版本、原生报告及打开结果存放于artifacts/debug-positions的独立编号目录。

可见窗口自动通过真实数字键切换到当前选择者或行动者；之后由你手工控制，不再自动推进场景。取消只清除本地预选，已经支付的弃牌等事实不会撤回。游戏内保存使用独立QA存档；准备好的position.save.json保留原起点，可再次用run-player.ps1 -Qa -LoadSave完整路径打开。

已有跟踪窗口时，默认拒绝另开，不会默默关闭。只有明确传-ReplaceTrackedPlayer时才关闭已跟踪且路径匹配的Player。未知预设在生成局面之前失败。预设集合见tools/debug-positions.json；添加后须用-PrepareOnly核验其场景前缀、阶段、选择者和可继续性，再做实际窗口检查。
