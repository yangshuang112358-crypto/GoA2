# GoA2 v3 四人热座规则沙盒

这是 GoA2 v3 的独立实验仓库，不依赖 `goa2_v2` 的运行时路径。当前版本
提供一个窗口控制四个席位的热座测试流程，所有状态变化由 Python 后端校验。

## 当前可玩流程

1. 四个席位默认使用四名不同英雄，席位 0/2 对阵席位 1/3。
2. 点击席位面板切换当前控制席位。
3. 当前席位可选择英雄和初始手牌，确认前可以改选。
4. 已确认席位的牌对其他席位只显示为“已锁定”。
5. 四席全部确认后自动进入待翻牌阶段。
6. 点击“翻开全部”，后端读取四张正式卡牌的移动值并进入行动阶段。
7. 切换到有移动值的席位，点击后端标出的可达格，确认后执行移动。

正式移动由后端使用六方向 axial 邻接和 BFS 计算最短路径。障碍格与其他英雄
占用格不能进入或穿越，每进入一格消耗 1 点移动，暂不引入地形权重。一个
席位可以分多次移动，直到 `remainingMovement` 用尽。

四名英雄出生位置来自 v3 自己的 `data/map.json`，手牌和移动值来自
`data/cards.json`。卡牌目录包含 6 名英雄和 108 张正式卡牌。

## 调试工具

页面保留独立的“调试工具”区域，当前按钮都连接到真实后端命令：

- 重置对局；
- 切换控制席位；
- 强制全部确认，未选牌席位自动选择手牌第一张；
- 强制翻牌；
- 补满当前席位移动值，数值重新读取其已翻开的正式卡牌；
- 选择席位后点击地图格传送英雄。

传送会校验坐标存在、格子可站立且没有单位占用，不消耗移动值。金币、轮末
和击杀工具将在经济、回合与伤害系统接入后再实现，本轮不提供无效按钮。

## 卡牌效果状态

- `未实装`：正式数据和规则文字已录入，尚无对应规则代码；
- `已实装未测试`：已有初步规则代码，但缺少完整自动化验证；
- `已测试`：已有自动化回归测试覆盖。

状态目录集中在 `engine/cards.py`，页面不维护独立名单。初始手牌规则为金卡、
银卡各一张，再从红、绿、蓝三个技能色中各选源数据顺序里的第一张 1 级牌。

## 运行

在 `goa2_v3` 目录运行：

```powershell
python -B demo_server.py
```

打开：

```text
http://localhost:3217/
```

运行测试：

```powershell
python -B tests/run_tests.py
```

## 当前边界

四人热座共享同一后端状态，但这不是多窗口联网。真正的多窗口模式仍需要
room、player token 和 polling 或 WebSocket。

尚未实现：

- 基础攻击、防御、伤害、死亡和击杀；
- 回合、金币和升级；
- 完整卡牌文字效果；
- 多窗口同步、大厅、回放和持久化。

当前已实现后端权威的基础攻击目标选择和攻击声明：网页会高亮合法英雄目标，
确认后记录攻击距离、基础伤害和当前最终伤害，并阻止同一席位重复使用主要行动。
攻击英雄会创建可序列化的防御选择窗口，由被攻击席位弃置防御牌或选择死亡；
相邻小兵目标会直接被基础攻击击败。当前仍是四席热座，真实多人身份 token、
复活、奖励与完整回合队列尚未接入。
