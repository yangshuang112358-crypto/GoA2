# 卡牌效果系统与逐卡实施手册

## 1. 目标

让 108 张复杂卡牌可扩展、可暂停选择、可联网、可回放、可测试。
不得把大量特殊效果塞进主回合、攻击、移动或 UI 流程。

## 2. Effect Schema 概念

Schema 是卡牌效果的结构化合同，描述：

- 触发时点；
- 原子步骤顺序；
- 谁选择；
- 合法目标；
- 强制或可选；
- 无目标行为；
- 保存的中间结果；
- 事件；
- 持续时间；
- 来源和优先级。

Schema 不是直接执行的卡牌文字，也不是第二套规则。

## 3. 顶层分类

- Primary Action；
- Defense Effect；
- Instant Effects；
- Triggered Effects；
- Continuous Effects；
- Replacement Effects；
- Custom Handler。

## 4. 原子步骤建议

- ChooseTarget；
- ChooseCell；
- ChooseCardFromHand；
- ConfirmChoice；
- Move；
- Push；
- Place；
- Swap；
- Attack；
- Defend；
- Discard；
- Retrieve；
- Gain/LoseGold；
- Defeat；
- Add/RemoveEffect；
- Branch；
- Repeat；
- EndCard。

每步只处理一个目标。多个目标使用多个步骤或受控 Repeat。

## 5. Pending Choice

任何玩家选择都必须形成可序列化对象：

- choice ID；
- source；
- chooser seat；
- legal options 或可重复计算的 query；
- required/optional；
- current step；
- stored references；
- revision；
- cancel policy；
- expiry。

不得依赖“当前打开的 Unity 弹窗”保存规则进度。

## 6. Event Window

统一顺序：

1. Intent accepted；
2. Before；
3. Replacement / Prevention；
4. Resolve；
5. After；
6. Trigger collection；
7. Trigger resolution；
8. Cleanup / Expiry。

同一窗口多个效果的优先级必须来自规则、控制者选择或稳定 sequence，
不得依赖 C# 容器遍历偶然顺序。

## 7. Custom Handler 边界

只有以下情况使用：

- 通用 Schema 表达反而更复杂；
- 独特循环或替换；
- 当前 Schema 没有该 primitive；
- 确定性或性能有明确要求。

Custom Handler 仍必须：

- 通过统一 Command/Event；
- 使用 Pending Choice；
- 记录 source；
- 支持序列化与 Replay；
- 不操作 UI；
- 有完整行为矩阵；
- 不修改主流程。

## 8. 一张卡的标准流程

### 步骤 A：读取权威信息

- 用户最新裁定；
- 正式卡牌条目；
- v5 规则；
- 相关卡牌和 primitives；
- v4 只作证据。

### 步骤 B：Card Contract

记录：

- ID、英雄、颜色、等级、先攻；
- 主要行动族和值；
- 次要移动、防御、范围/远程；
- 卡牌文字；
- 被动；
- 触发和 duration；
- 实现状态。

### 步骤 C：拆元动作

每步写：

- timing；
- required；
- chooser；
- target；
- range；
- exclusions；
- immunity；
- storeAs；
- no-target；
- event；
- failure atomicity。

### 步骤 D：提出问题

只有问题会改变以下内容时才阻塞：

- 合法目标；
- 顺序；
- 强制/可选；
- 持续时间；
- 替换/防止；
- 交互结果。

问题必须使用最小场景和 2-3 个明确解释。

### 步骤 E：测试矩阵

先写测试名称和预期，再写代码。

### 步骤 F：实现

1. 添加失败测试；
2. 增加最小通用 primitive；
3. Schema 接线；
4. 必要时 Custom Handler；
5. 运行牌自身测试；
6. 运行交互测试；
7. 运行全量 Rules/Card tests；
8. Play Mode UI 验证；
9. Multiplayer 私有选择验证。

### 步骤 G：状态提升

按证据提升，不能跳级。

## 9. 卡牌小组实施顺序

1. 单目标纯数值攻击；
2. 单目标移动；
3. 弃牌和取回；
4. 推动；
5. 放置与交换；
6. 多步骤攻击；
7. Repeat；
8. 本回合/下一回合持续；
9. Trigger；
10. Replacement/Prevent；
11. Immunity；
12. 六名英雄紫色持续被动。

每组最多包含共享同一 primitive 的少量卡牌。

## 10. 逐卡任务 Prompt 模板

```text
本次只处理卡牌：[ID 和名称]。

读取：
- v5构建指示/02_GoA2_v5权威游戏规则.md
- v5构建指示/09_卡牌效果系统与逐卡实施手册.md
- 正式卡牌条目
- 相关已有 primitives 和测试

先不要实现。先输出：
1. Card Contract；
2. 逐元动作；
3. 每步 chooser、target、required、no-target；
4. Trigger/Continuous/Replacement 分类；
5. 需要用户确认的问题；
6. 建议 Schema 或 Custom Handler；
7. 完整测试矩阵；
8. 下一步只实现的最小 primitive。

不得从旧代码猜规则，不得修改主流程，不得一次处理其它卡。
```

## 11. 评审卡牌实现

检查：

- 目标阵营是否正确；
- required 是否可被跳过；
- optional 是否无法跳过；
- 无目标是否死锁；
- 多目标是否错误地同时处理；
- chooser 是否正确；
- 失败是否部分修改；
- source/duration 是否丢失；
- 是否可序列化；
- 是否能 Replay；
- 是否泄漏私有信息；
- 是否在主流程写 card ID；
- 测试状态是否夸大。
