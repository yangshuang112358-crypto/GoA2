# 待确认规则与风险登记

## 1. 已解决且不得重复询问

- 正式地图已经校验，不再检查对称性。
- 所有可通行地形移动费用相同。
- 不会同时触发水晶和战线胜利。
- 第四回合产生的下一回合效果直接失效，无例外。
- 六名英雄紫卡全部为持续被动。
- 单个元动作不同时处理多个目标。
- 多目标由效果来源控制者决定顺序。
- 快速移动起始区和目标区均不能有敌方单位。
- 起始区和目标区可相同。
- 障碍分隔区域不相邻。
- 基础攻击未特别说明时只选相邻敌方单位。
- 最终攻击值再低也必须出防御牌。
- 重型小兵被移除立即推进。
- 默认第三次推进取得中圈获胜。
- 第四回合结束自动轮末。
- 多名玩家升级时同步选择自己的升级。

## 2. 逐卡实现时确认

- 复杂卡牌的具体逐元动作；
- 可选与强制窗口；
- 替换、防止、免疫交互；
- 多个持续/触发效果的优先级；
- “最多”“如果可能”“否则”“重复”等精确语义；
- 具体卡牌是否允许友方目标；
- 感叹号防御的正式触发条件；
- 小兵离开战区后的路线选择细节；
- 卡牌导致的特殊胜利或规则例外。

## 3. 开工前仍需产品决定

- v5 首发平台：Windows only，还是同时考虑 WebGL/移动端？
- 最终联网模式：玩家 Host、Relay，还是 Dedicated Server？
- 是否需要账号系统、好友、匹配和排行榜？
- 观战、回放分享和断线托管的优先级？
- UI 使用 UI Toolkit 还是 uGUI？
- 美术目标：功能桌面版、2D 棋盘、伪 3D 或完整 3D？
- 输入：仅鼠标，还是手柄和触屏？
- 是否包含 AI 玩家？
- 本地热座是否为正式功能？
- 发行平台和合规要求。

这些问题不阻塞 M0-M7 的纯规则开发，但会影响 UI、网络和发布架构。

## 4. 主要工程风险

### 规则漂移

风险：对话中的新裁定未写入规则，Agent 使用旧文档。

措施：任何规则修改先更新 `02` 和本文件，再写测试。

### Unity 与规则耦合

风险：规则散落 MonoBehaviour，难测试、难服务端复用。

措施：Rules Core 禁止引用 UnityEngine，CI 检查程序集依赖。

### 卡牌硬编码

风险：108 张牌形成巨大 switch/if。

措施：Effect Schema、通用 primitive、Custom Handler 注册和评审门槛。

### 多人身份混用

风险：热座显示字段被错误当成多人授权，v4 已发生过。

措施：授权只使用 Player Identity/ClientId；显示控制状态不参与规则权限。

### Pending Choice 丢失

风险：选择只存在 UI，断线后死局。

措施：所有选择进入 GameState，序列化与重连测试为合并门槛。

### 过早联网

风险：规则尚未稳定就被网络生命周期绑死。

措施：先纯规则、再本地四席、再联网垂直切片。

### 测试状态虚高

风险：有一个测试就宣称卡牌完成。

措施：五级状态和完整矩阵，Test Agent 独立审查。

### Unity 版本和包漂移

风险：成员 Unity patch 或 Packages 不同。

措施：锁定 Unity 6.3 LTS patch、提交 lock 文件、升级需 ADR 和专门 PR。

### Git 大文件与缓存

风险：Library、Build、临时资产进入仓库。

措施：Unity `.gitignore`、提交前检查、需要时评估 Git LFS。
