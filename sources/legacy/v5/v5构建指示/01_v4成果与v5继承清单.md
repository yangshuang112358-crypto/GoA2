# v4 成果与 v5 继承清单

## 1. v4 已验证的资产

- 正式地图：254 个 axial 六边形格，44 个障碍格。
- 地图区域：双方泉水、双方近区、中区、上下草丛、障碍区。
- 正式卡牌：6 名英雄、108 张卡。
- 英雄：黄蜂、夏尔加萨、布罗根、艾瑞恩、虎爪、萨彼娜。
- 所有具体卡牌状态仍为 `data_only` / `未实装未测试`。
- v4 当前有 135 项自动化测试通过。

v5 可以迁移 `goa2_v4/data/cards.json` 与 `goa2_v4/data/map.json` 的内容，
但应先建立 Unity 侧数据导入校验，不直接把旧 JSON 当成运行时对象。

## 2. v4 已实现并通过测试的规则能力

### 房间与状态

- 四席、2 对 2、队伍和队长。
- 可配置英雄、水晶生命和战线胜利阈值。
- 权威 Game State、revision 乐观并发检查。
- JSON 持久化、原子替换、损坏文件隔离。
- 私有手牌投影、玩家 token、重连和多窗口轮询同步。

### 选牌与行动队列

- 每席从五张手牌暗选。
- 确认前可改选，确认后锁定。
- 四席确认后自动翻牌。
- 修正先攻排序。
- 同队同先攻由队长选择。
- 跨队同先攻使用并翻转决策币。
- 当前行动者可选主要行动、次要移动、快速移动或跳过。
- 选择行动后可取消或改选。
- 第四回合结束后自动进入轮末。

### 地图与移动

- 英雄出生、占位、障碍阻挡。
- 普通移动使用服务端 BFS 合法路径。
- 所有通行地形移动费用均为 1。
- 快速移动可到当前或相邻区域。
- 快速移动要求起始区和目标区均无敌方单位。
- 障碍分隔的区域不算相邻。
- 主要移动可替换为快速移动，替换后不执行主要文本。

### 基础战斗

- 攻击族卡牌当前可选择相邻敌方英雄或小兵。
- 英雄攻击进入可序列化的 Pending Attack。
- 小兵支援和防御修正参与最终攻击值。
- 最终攻击值可以低于 0，但英雄仍需打防御牌。
- 防御值足够则成功，不足则被击败。
- 感叹号防御视为任意防御值。
- 近战、远程、重型小兵和英雄击败奖励。
- 英雄按等级损失水晶生命。
- 英雄待复活并在自己卡牌行动时选择出生点。

### 小兵、兵线和胜利

- 当前战区与三个战斗区域。
- 双方各 4 近战、1 远程、1 重型。
- 重型小兵在其它友方小兵存活时受保护。
- 重型小兵被移除后立即推进，不要求等到轮末。
- 轮末数量差由少兵方队长选择移除。
- 重型小兵最后移除。
- 推进后清除并在新战区重生小兵。
- 出生点被占用时由队长选择相邻合法格。
- 第三次推进取得中圈或推进至敌方泉水立即胜利。
- 水晶归零胜利。

### 金币、等级与升级

- 轮末按当前英雄等级自动连续支付升级。
- 不能升级者获得 1 金补偿。
- 红绿蓝升级牌二选一。
- 选中牌替换手牌，未选牌提供永久被动。
- 永久攻击、防御、移动、先攻、范围、远程加成参与计算。
- 同类加成聚合显示。
- 8 级解锁紫色持续被动。
- 多名玩家的升级选择可同步、各自独立完成。

### UI 与调试需求

- v2 三栏信息布局和 v3 深色配色已形成需求基线。
- UI 区域：房间与调试、玩家席位、公开行动、行动按钮、地图、手牌、
  日志、卡牌目录。
- 地图可缩放。
- 卡牌显示主要行动、次要移动、次要防御、范围/远程。
- 卡面数值以 `基础值+永久加成` 显示。
- 调试工具包括重置、强制选牌、传送、跳过当前/全部、设置资源、
  击败英雄、重置/移除小兵、推进战线、轮末工具。

## 3. v4 尚未完成

- 108 张具体卡牌效果全部未实装、未完成逐卡测试。
- Effect Schema 只是草案，没有完整运行时解释器。
- 详细规则事件日志、完整回放和观战仍不成熟。
- 正式 Lobby、Matchmaking、Relay、专用服务器部署未完成。
- 断线重连虽有本地持久化测试，但没有生产级账号、安全和跨网络验证。
- UI 仍是功能原型，不是最终 Unity 美术与动画品质。
- 无完整音频、特效、教程、设置、可访问性和发布流程。

## 4. v5 应继承什么

- 规则裁定和测试场景。
- 地图、英雄、卡牌的正式数据。
- Command -> Validate -> Reduce -> Event -> State 的权威思想。
- 公共状态与玩家私有状态分离。
- Pending Choice 必须可序列化。
- 服务端/主机权威，客户端只提交 Intent。
- 规则层不依赖 UI、网络和 Unity 场景。
- 调试工具是正式研发能力，不是临时垃圾代码。

## 5. v5 不应继承什么

- Python 和网页代码本身。
- 全局可变房间字典。
- 热座 `controlledSeat` 与多人身份混用。
- 依赖浏览器本地存储解决身份的产品方案。
- 把合法性写在前端。
- 在主流程中按 card ID 分支。
- 把测试通过等同于具体卡牌已完成。
- 先做完整 UI，再补规则测试。

## 6. v5 的完成定义

“完整”至少要求：

- 基础规则、完整回合、兵线、升级、胜负全自动测试；
- 108 张卡全部达到 `integration_tested`；
- 四客户端真实联网、重连、非法命令和信息隐藏测试；
- 回放能从初始状态与 Command/Event Log 重建；
- Unity 构建可运行，不依赖 Editor；
- 发布前测试、性能、日志、版本和回滚流程齐全。
