# v5 里程碑与验收门槛

原则：每个里程碑都必须可运行、可展示、测试为绿。不要同时启动多个未完成里程碑。

## M0 文档与环境锁定

目标：

- 阅读本指示包；
- 安装并锁定 Unity 6.3 LTS patch；
- 建立 Git 仓库、Unity `.gitignore`、README、ADR 目录；
- 确定 URP、测试框架和包版本。

验收：

- 新成员克隆后能用同版本 Unity 打开；
- 空工程无编译错误；
- 一个 Edit Mode 示例测试和一个 Play Mode 示例测试通过；
- 首次提交和 tag 完成。

## M1 纯 C# 规则骨架

目标：

- Domain、Rules、Application 程序集边界；
- GameState、Command、Event、Result；
- revision、原子失败、序列化 round-trip；
- 确定性随机接口。

验收：

- Rules 不引用 UnityEngine；
- 同一初始状态和命令序列得到相同结果；
- 非法命令不改变状态；
- Edit Mode 全绿。

## M2 正式数据导入

目标：

- 导入并校验 254 格地图；
- 导入 6 英雄、108 卡；
- 所有卡标记 `data_only`；
- ID、引用、颜色、等级、初始手牌校验。

验收：

- 数据数量与 hash 报告；
- 无重复 ID；
- 初始手牌规则正确；
- Unity Inspector 或调试页面可浏览内容。

## M3 本地四席选牌与先攻

目标：

- 房间配置、英雄选择；
- 四席私有手牌模拟；
- 暗选、改选、确认、自动翻牌；
- 先攻、同队队长选择、决策币翻面；
- 四回合生命周期。

验收：

- 单进程四席完整走完一轮；
- 私有视图测试；
- 同先攻全部分支；
- 第四回合自动进入轮末。

## M4 地图、英雄与移动

目标：

- Unity 六边形地图表现；
- 权威坐标与占位；
- 英雄出生；
- 普通移动与快速移动；
- 取消、改选、确认目标；
- 地图缩放和调试传送。

验收：

- 规则测试覆盖路径边界、障碍、占位、区域敌人；
- UI 只高亮 Rules 返回目标；
- 快速移动规则全部测试；
- Player 构建可操作。

目标：

## M8 Unity 完整本地 UI

目标：

- v2 信息布局与 v3 配色的 Unity 版本；
- 八个 UI 区域；
- 完整调试面板；

## M11 逐卡实装

顺序建议：

1. 纯数值与单目标；
2. 移动、推动、放置、交换；
3. 弃牌、取回、金币；
4. 重复和分支；
5. 触发与持续；
6. 替换、防止、免疫；
7. 六张紫色持续被动。

每张卡必须经历：

`data_only -> specified -> implemented -> behavior_tested -> integration_tested`

验收：108 张卡全部达到 `integration_tested`，不存在“默认算已完成”。
